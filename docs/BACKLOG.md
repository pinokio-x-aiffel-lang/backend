## 확장 경로

### 1. 연속·추세 주장 분해 (decompose)

- **배경**: "세 달 연속 감소(9월 -0.4%·10월 -0.2%·11월 -0.4%)"처럼 개별 수치가
  병기된 추세 문장은 현재 비-claim 처리(프롬프트 규칙) + 개별 수치만 추출한다.
  분해를 자동화하면 합본 claim(`value="-0.4%/-0.2%/-0.4%"`) 문제의 근본 해결이 된다.
- **방안**: [2] 추출 후처리 또는 프롬프트 강화로 "N개 시점 × N개 수치" 병기 문장을
  시점별 claim N개로 자동 분리. 검증은 기존 단일 claim 체인을 그대로 사용.
- **선결**: 1 claim = 1 수치 · 1 시점 프롬프트 규칙(적용 예정)의 효과 측정 후,
  남는 합본 빈도가 유의미할 때 착수.

### 2. 추세 claim_type 신설 + HITL 라우팅

- **배경**: 개별 수치가 병기되지 않은 순수 추세 주장("10개월째 증가세",
  "33년 만에 최장")은 현행 스키마(단일 period 슬롯 + 단일 비교)로 검증 불가.
  지금은 비-claim으로 폐기되어 팩트체크 대상에서 누락된다.
- **방안**: `ClaimType.TREND` 신설 → [7] `_SKIP_TYPES`에서 제외하되 수치 비교는
  우회 → `needs_hitl=True` + `HitlCategory.DATA_AMBIGUITY`로 사람 검토 라우팅.
  검증을 포기하는 대신 누락도 하지 않는 절충.
- **선결**: HITL 운영 플로우([7]~[10] needs_hitl 처리)가 실사용 가능해진 뒤.
  스키마 확장(연속 기간 표현: `period_value` 다중화 또는 범위형) 설계 필요.

- **선결**: 없음 — 두 군데 수정으로 즉시 가능. [3] 이후는 이미 대응되어 있음.

### 4. [3] value 정규화 — 룰 우선·LLM 최후 재구성

- **배경**: `_parse_value`의 or-체인에서 `parse_korean_numeral`이 내부 LLM 폴백까지
  수행해, 룰(`_parse_number_rule`)이 정답을 낼 수 있는 입력("2858만9000명")이
  LLM 환각(스케일 오류)으로 오염. gold 채점 value 오답 45건 중 29건이 이 경로.
- **방안**: 룰 전부(`_try_*` + `_parse_korean_numeral_rule` + `_parse_number_rule`)
  먼저 → 전부 실패 시에만 `_llm_parse_number` 1회.
  부수 효과: 건당 LLM 호출 급감(평균 0.4s → 룰 적중 시 ~0s).
- **추가**: `_try_change` 확장(절대단위 증감 부호: "8만3000명 줄었다"→`-83000`, 14건),
  `_INCREASE/_DECREASE`에 급증·급감·반등 등 보강, `_try_range` 단위 suffix 허용(2건).

### 5. [3] compare 기준점 컨벤션 — period 기준 해소

- **배경**: 동기형 비교 표현("전년 동월")을 코드는 기사 작성일(base) 기준으로,
  gold 는 claim 시점(period) 기준으로 해석. base 2025-04 · period 2025-03이면
  코드 2024-04 vs gold 2024-03 — 한 달 어긋남(gold 채점 compare 오답 43건의 주인).
- **방안**: `_normalize_one`에서 period 먼저 해소 → `_resolve_compare(raw, period, base)`
  신설(연도−N + 서픽스 유지 문자열 연산; 미해당 표현은 base 폴백).
- **선결**: 규약 확정 — ① "1년 전"이 분기 period일 때 연도 강등(gold 현행) vs `YYYY-Qn`
  유지, ② "작년 말" = `2024`(gold) vs `2024-12`(현행 코드, R1 수정 후) 통일.
