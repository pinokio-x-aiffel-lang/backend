# 한국어 자연어 산술 표현 파싱 명세

> **대상 독자**: `parse_numeric_expression`(자연어 수치 표현 → 수치값) 구현 코딩 에이전트/개발자.
> **목적**: 한국어 자연어 산술 표현을 수치값으로 변환하는 규칙의 단일 출처(single source of truth).
> **근거**: deep-research(2026-06-02, 논문 23편 조사·25주장 3표결 검증/19통과) + 국립국어원 규범 보완 + 2026-06-03 추가 조사(어림수·겹수사·주관적 수량·비율단위·큰/작은 수 단위, §9 13~17). 상세 출처는 [§9](#9-근거-문헌).
> **관련 코드**: `src/numeric/parse_numeric_expression.py`(신설 예정), `src/modules/normalize_claim.py`, `src/modules/calculate_metric.py`, `src/kosis/units.py`, `src/schemas/runtime.py`.
> **현재 구현 현황**: 본 문서는 *목표 스펙*이다. 지금 런타임 룰(`_parse_value`/`_normalize_period`)이 실제 커버하는 범위·**의도적 미커버 결정**은 `docs/numeral_parser_coverage.md` 참조.

---

## 0. TL;DR (구현 요약)

- **입력**: 한국어 텍스트 조각 1개. 예) `"약 23만"`, `"1조 2천억"`, `"전년대비 3.2% 증가"`, `"5분의 1"`, `"3할 2푼"`.
- **출력**: 대표 수치값(`float | None`) + 메타 플래그(근사/경계/상대비교/%p 등). 제안 스키마는 [§6](#6-출력-스키마-제안).
- **핵심 원칙**
  1. **규칙 기반 우선**. 순수 신경망 정규화는 숫자에서 'silly error'(전혀 다른 수)를 냄 → 규칙/검증 결합 필수(Sproat&Jaitly 2016).
  2. 한국어 큰 수는 **10⁴(만) 단위로 묶임** — 영어 10³와 다름.
  3. 수사 계열(고유어/한자어)은 **인접 단위명사가 결정** — 숫자를 고립적으로 처리 불가.
- **범위 밖**: 수학 문장제 연산식 추출(§4 ⑦), 단위 차원 변환(이미 `src/kosis/units.py`가 담당), 시점 표현 정규화("전년"→연도)는 `normalize_claim`의 `period_value` 쪽.

## 1. 범위와 방향

### In-scope
- 정수/실수 표기, 천단위 쉼표, 소수점 (`"1,200"`, `"3.2"`)
- 큰 수 단위 `만/억/조/경` + 보조단위 `천/백/십` 복합 (`"1조 2천억"`)
- 비율·분수·할푼리·배수 (`"5분의 1"`, `"3할"`, `"2배"`, `"32%"`)
- 근사·범위·증감·비교 표현의 **플래그 추출** (`"약"`, `"안팎"`, `"이상"`, `"전년대비"`, `"%p"`)
- 어림수 접두·겹수사 (`"수십"`, `"몇백"`, `"십수"`, `"여남은"`, `"두세"`, `"서너"`)
- 비율 단위 확장(`‰`/`bp`/`ppm`), 음수(`"영하 5도"`, `"마이너스 3%"`), 0·소수점 읽기(`"영점오"`)
- 주관적 수량 강조 부사의 **플래그 추출** (`"무려"`, `"불과"`, `"겨우"` — 값 불변)

### Out-of-scope
- 문장 → 연산식(사칙연산) 변환 = 수학 문장제(MWP) 영역. 분류 체계만 참고(§4 ⑦).
- 단위 차원 변환(명↔달러 등) = `src/kosis/units.py`.
- 시점 자연어(`"전년"`→`"2023"`) = `normalize_claim`이 `period_value`에서 별도 처리.

### ⚠ 방향 주의 (중요)
검증 통과 문헌(KIISE2021, CALCS2020, g2pK, SMART-G2P, POSTECH1998)은 **전부 '숫자 → 한국어 발음(verbalize)' 방향**(TTS/G2P 정규화)이다. 본 파서는 **'표현 → 수치값'의 역방향**(inverse text normalization, ITN). 문헌의 **수사 계열 선택 규칙·문맥 의존성·기호적 제약 필요성**은 그대로 유효하나, **파싱 알고리즘을 직접 제공하지는 않으므로** 변환 규칙은 본 문서에서 자체 정의한다.

| 등급 | 의미 | 적용 |

| ✅ | 검증 통과 학술 문헌 근거 | 수 읽기 체계, 만/억/조, 수학 문장제 분류 |
| ⚠ | **전용 검증 학술 문헌 미확보** → 국립국어원 규범·표준국어대사전으로 보완 | 근사·범위·증감·비교·할푼리·어림비율 |

## 3. 핵심 변환 규칙 (machine-actionable)

### 3.1 큰 수 단위 multiplier ✅
```python
BIG_UNIT = {"십": 10, "백": 100, "천": 1_000,
            "만": 10**4, "억": 10**8, "조": 10**12, "경": 10**16,
            # 확장(실사용 희박, 과학·관용): 경 위로 4자리(10⁴)마다 상승
            "해": 10**20, "자": 10**24, "양": 10**28, "구": 10**32,
            "간": 10**36, "정": 10**40, "재": 10**44, "극": 10**48}
# 작은 수 단위(소수, 현대 거의 미사용) — 할푼리(비율)와 별개의 절대-소수 체계
SMALL_UNIT = {"분": 1e-1, "리": 1e-2, "호": 1e-3, "사": 1e-4, "홀": 1e-5, "미": 1e-6}
```
- 파싱: 텍스트를 큰 단위(조→억→만) 경계로 분할 후 **각 그룹값 × 단위 multiplier 를 누적 합산**.
- `"1조 2천억"` = `1*10**12 + 2000*10**8` = `1.2e12`.
- `"3억 5천만"` = `3*10**8 + 5000*10**4` = `3.5e8`.
- `"23만"` = `23*10**4` = `230000`.
- 단위 사이 공백/생략 모두 허용. 큰→작은 단위 순서로 등장.

### 3.2 아라비아 + 단위 혼합 ✅
- 천단위 쉼표 제거(`"1,200"`→`1200`), 소수점 보존(`"3.2"`→`3.2`).
- 숫자부와 단위명사/조사 분리: `"23만 명"` → 수치 `230000`, 단위 `"명"`.

### 3.3 수사 계열 (읽기 방향 — 역파싱 시 매핑 테이블) ✅
| 계열 | 형태 | 비고 |
|---|---|---|
| 한자어 | 일·이·삼·사·오·육·칠·팔·구·십·백·천 | 금액·날짜·%·측정값·만/억/조와 결합. 단위 클수록 한자어 경향 |
| 고유어 | 하나·둘·셋·넷·다섯…열·스물(스무)·서른…아흔 | 분류사·나이(살)·시(時). 관형형: 한·두·세·네·스무 |
| 서수 | 첫째·둘째 / 제N·N번째 | 기수와 구분 |

> 같은 숫자도 인접 단위가 계열을 바꾼다: `12시`=열두(고유어), `12분`=십이(한자어). 한글 수사 입력을 파싱할 때 이 매핑이 필요(아라비아 입력이면 불필요).

### 3.4 비율·분수·전통 비율
| 표현 | 규칙 | 예 | 등급 |
|---|---|---|---|
| 퍼센트 | `÷100` | `"32%"`→`0.32` (또는 비율 컨텍스트에 따라 `32` 유지) | ✅ |
| 분수 `N분의 M` | `M / N` (**분모가 먼저**) | `"5분의 1"`→`0.2` | ✅ |
| 비 `A 대 B` | 비율 `A:B` | `"2 대 1"`→`2.0` | ✅ |
| 할·푼·리·모 | 할=0.1·푼=0.01·리=0.001·모=0.0001 누적 | `"3할 2푼"`→`0.32` | ⚠ |
| 어림 비율 | 정성→근사 | 절반·반≈0.5, 과반>0.5, 대다수≈0.7+, 거의≈1.0 | ⚠ |
| 어림 비율(확장) | 정성→근사 | 대부분≈0.8+, 절대다수≈0.9+, 태반>0.5, 일부=소량, 극소수≈0 | ⚠ |
| 천·만·백만분율 | `‰÷1000`, `bp÷10000(=0.01%p)`, `ppm÷10⁶` | `"50bp"`→`0.005`(=0.5%p) | ⚠ |

### 3.5 배수 ⚠
```python
MULTIPLIER = {"배": "×N", "갑절": 2.0, "곱절": 2.0, "배가": 2.0,
              "절반": 0.5, "반": 0.5, "반토막": 0.5}
```
`"2배"`→기준값 ×2, `"절반"`→×0.5. (기준값이 있어야 절대 수치화 가능 → relative 플래그)
`곱절`=`갑절`(2배). `배가(倍加)`는 증가(sign=+1), `반토막`은 감소(sign=−1) 방향을 함께 가짐.

### 3.6 퍼센트포인트 ⚠
- `%p`(퍼센트포인트) ≠ `%`. **두 퍼센트 값의 절대 차**. `is_percent_point=True`로 분리. 혼동 시 검증 오류 직결.
- 관련 비율 단위: `bp`(베이시스포인트)=만분율=`0.01%p`, `‰`=천분율, `ppm`=백만분율(§3.4). `bp`↔`%p` 혼동 주의.

### 3.7 어림수 접두·겹수사 ⚠
- **`數-` 접두**(수십·수백·수천·수만·수십만): 자릿수 단위 × 어림 → `approx=True`. 국립국어원상 `수십`="십의 두서너 배"(≈20~90), `수백`≈200~900.
- **`몇-`**(몇십·몇백·몇천): 미상 자릿수 어림 → `approx=True`(또는 자릿수 범위).
- **`십수(十數)`**: '십을 약간 넘는 수' = 11~19. `십수만`=십몇만. ⚠ `수십`(20~90)과 **방향 반대** — 혼동 금지.
- **`여남은`**: '열이 조금 넘는 수' ≈ 10~12.
- **겹수사(고유어 병렬)**: 인접 두 고유어 수의 어림 구간 → `range=[n, n+1]`.
  `한두`(1~2)·`두세`(2~3)·`두서너`(2~4)·`서너`(3~4)·`너덧`/`네댓`(4~5)·`대여섯`(5~6)·`예닐곱`(6~7)·`일고여덟`(7~8)·`여덟아홉`(8~9).

### 3.8 주관적 수량 강조 부사 (값 불변·플래그만) ⚠
수치값은 **그대로 두고** '화자 인식' 플래그만 부여. 파싱에서 소비하되 **무시 금지**(framing 정보).
```python
SUBJECTIVE = {  # subjective="large"|"small"
    "large": ["무려", "자그마치"],                              # +조사 -(이)나
    "small": ["불과", "겨우", "고작", "기껏해야", "단지"],       # +-뿐/-밖에, -에 불과/그치다/지나지 않다
}
```

### 3.9 음수·0·소수점 읽기 ⚠
- **음수**: `영하 N`→`−N`(온도), `마이너스 N`→`−N`, 적자/손실 문맥=음수, 재무제표 `△`·괄호 `( )`=음수.
- **0 읽기**: `영(零)`/`공(空)`/`제로`. 코드·전화=공(공일공), 수·소수=영.
- **소수점**: `점`. 소수부는 **자리별 개별** 읽기 — `"영점구일"`=`0.91`(≠ 0.91→"구십일"). *(한글 수사 입력 시만; 아라비아 입력이면 불필요, §3.3와 동일 단서.)*

### 3.10 도달·비교 동사 ⚠ (경제·통계 기사 빈출)
- `달하다`·`이르다` = 그 수치에 **도달**(=값 확정, bound 없음). `"100억에 달하다"`→`1e10`.
- `육박` = 근접 미달(≈ `가까이`의 동사형). `"1만에 육박"`→하한 근접.
- `웃돌다`·`상회(上廻)` = 기준 **초과**(>); `밑돌다`·`하회(下廻)` = 기준 **미만**(<). `초과`/`미만`의 비교기준형 → `relative_to` 결합.
- `내지(乃至)` = 구간 `[A, B]`. 단 '또는' 뜻도 있어 모호(법령은 구간 의미로만 사용, §3 외부에서 disambiguation).

## 5. 파싱 알고리즘 스케치 (의사코드)

```
parse_numeric_expression(text) -> NumericValue:
    raw = text
    # 1) 전처리: 공백 정규화, 천단위 쉼표 제거
    # 2) 플래그 추출 (정규식, 소비 후 잔여 텍스트 계속 처리)
    approx   = matches(r"(약|대략|얼추|가량|쯤|안팎|내외|여\b|남짓|가까이)")
    bound    = "gte" if "이상" else "lte" if "이하" else \
               "gt"  if "초과" else "lt"  if "미만" else None
    relative = "전년대비"|"전월대비"|... -> baseline 키
    is_pp    = "%p" in text or "퍼센트포인트" in text
    sign     = +1 if 증가류 else -1 if 감소류 else None

    # 3) 비율/분수/할푼리 우선 처리 (전용 패턴)
    if "분의" in text: value = parse_fraction(text)          # M/N
    elif 할푼리_pattern: value = parse_hapunri(text)          # 0.1/0.01/...
    elif "%" 또는 "퍼센트": value = parse_percent(text)
    elif "배"|"절반"|"반"|"갑절": value, relative = parse_multiplier(text)

    # 4) 일반 수치: 아라비아 + 큰수단위 복합
    else: value = parse_number_with_units(core_text)          # §3.1

    return NumericValue(value=value, raw=raw, approx=approx,
                        bound=bound, relative_to=relative,
                        is_percent_point=is_pp, sign=sign, ...)
```

`parse_number_with_units` 핵심(§3.1):
```
def parse_number_with_units(s):
    total, segment = 0, 0
    for token in tokenize(s):           # 숫자 또는 단위
        if is_digit(token): segment = float(token)
        elif token in {"십","백","천"}: segment *= BIG_UNIT[token]   # 보조단위는 직전 수에 곱
        elif token in {"만","억","조","경"}:
            total += segment * BIG_UNIT[token]; segment = 0          # 큰 단위에서 누적·리셋
    return total + segment
```

## 6. 출력 스키마 제안

> 제안일 뿐 강제 아님. 기존 `ValueSlot`(raw/llm_value/is_inferred)과 매핑하는 어댑터를 둘 것.

```python
@dataclass
class NumericValue:
    value: float | None        # 대표 수치(점추정). 파싱 불가 시 None → 호출부에서 NEI
    raw: str                   # 원문 표현
    value_kind: str            # WEB_API_CONTRACT claim_type enum 재사용:
                               #   absolute|change_rate|ratio|distribution|comparison|metaphoric
    approx: bool = False       # 근사(약/가량/안팎/여/남짓)
    bound: str | None = None   # gte|lte|gt|lt|range
    range: tuple[float, float] | None = None
    is_percent_point: bool = False
    relative_to: str | None = None  # 전년/전월/전분기 등 비교 기준
    sign: int | None = None         # +1/-1 (증감 방향)
    subjective: str | None = None   # large|small — 무려·자그마치 / 불과·겨우·고작 (값 불변)
    unit: str | None = None
```

> **신규 필드 메모**: `value`는 음수 가능(영하·마이너스·적자·`△`/`( )` → `−값`). `range`는 겹수사·내지·전후·數- 접두에도 사용. `subjective`는 수치 무영향이나 framing 보존용(§3.8).

### 기존 설계 연동
- **claim_type enum 일치**: `docs/WEB_API_CONTRACT.md` §2.3의 `absolute/change_rate/ratio/distribution/comparison/metaphoric`를 `value_kind`로 그대로 사용. (설계의 "절대값/비율/증감률" 분류 = 본 표 ④~⑥과 대응.)
- **`normalize_claim`**: 각 `claim.value.llm_value`를 채울 때 본 파서 호출(`src/modules/normalize_claim.py` 현재 더미). 수치 표현→`value`, 시점 표현은 별도.
- **`calculate_metric`**: `bound`/`approx`/`is_percent_point`/`relative_to`를 비교 로직에 반영(예: 근사값은 허용오차 확대, %p는 차 비교, 경계는 부등식). 현재 `pass` 스텁.
- **`units.py`와 경계**: 본 파서는 **수치값**만, 단위 차원 변환은 `convert_to_claim_unit`. `unit` 필드만 넘기고 변환은 위임.

## 7. 엣지 케이스 / 함정

- `%p` vs `%`: 별개. `units.py` 메모에도 동일 경고(같은 그룹이나 의미 다름).
- 분수 어순: 한국어는 **분모가 먼저**(`5분의 1` = 1/5). 영어 직역과 반대.
- `절반/반`: 단독이면 ratio(0.5)일 수도, 배수(×0.5)일 수도 → 문맥(기준값 유무)으로 판단, 애매하면 `metaphoric` + `approx`.
- `여(餘)` 접미사: `100여 명`은 `100`이 아니라 `100 초과`(하한). 숫자에 바로 붙음.
- 큰 수 자리표기 생략: `2천억`에 `만` 없음 → 보조단위(천)×큰단위(억) 조합 처리.
- 근사·범위·증감·할푼리(⚠)는 학술 근거 약함 → 규칙을 보수적으로, 반드시 단위 테스트로 고정.
- 신경망 단독 금지: 순수 seq2seq는 숫자 silly error(전혀 다른 수). 규칙 우선, LLM은 보조/폴백.
- `십수`(11~19) ≠ `수십`(20~90): 방향 반대. 접두/접미 위치로 판별.
- `내지`: 구간 vs '또는' 모호. 법령·통계 문맥은 구간으로, 일반 문맥은 보수적으로 처리.
- `bp`(베이시스포인트) = `0.01%p`, `‰` = `0.1%`: `%`·`%p`와 단위 혼동 시 100배 오차.
- `무려/불과/겨우/고작`은 **값을 바꾸지 않음** — 제거하되 `subjective` 플래그로 보존(통째로 버리면 화자 의도 손실).
- 0 읽기: `영`/`공` 혼용. 소수부는 **자리별 개별** — `"영점구일"`=0.91이지 0.91→"구십일" 아님(역파싱 시 주의).
- `반토막`=감소(×0.5), `배가`=증가(×2): 부호 누락 주의.
