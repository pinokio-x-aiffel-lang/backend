# KOSIS Lookup (검색 → 메타 판독 → 선택 → 조회)

claim(주제·모집단·기간·수치)에 해당하는 **KOSIS 공식 셀 1개**를 찾는 절차.
사람이 KOSIS에서 직접 표를 뒤지듯, **표의 실제 구조(항목·분류축 코드)를 읽어** 고른다.
기존 [4] 트리 드릴다운 경로와 **병행**하는 대안 경로다.

API 레이어는 항상 `src/kosis/*`(Session·재시도·rate limit·`jsonVD=Y` 적용)를 경유한다.
- 검색: `search_tables(keyword)` → `statisticsSearch.do`
- 메타: `fetch_table_metadata(org, tbl)` → `getMeta`(ITM=항목·분류축, PRD=주기)
- 데이터: `call_kosis(params)` → `statisticsParameterData.do`

LLM 호출은 `traced_chat`(=`LlmCaller` 경유, Langfuse 기록)만, 파라미터는 `ModelPreset`만.

## 절차

핵심 통찰(내 수동 조회 과정): **도메인 → 조사(survey) → 차원(품목별/산업별) → 표 → 기간·원계열 → 셀**.
표를 고를 때 1순위 신호는 **조사명**이다(국내 정식 전국조사 ↑ / 국제기구·지역조사 ↓).

### 0. 검색 키워드 생성 (LLM) — 범주어 → 부모 차원어
주제에 특정 범주(제조업·석유류·서울)가 있으면 그건 보통 **표 안의 분류축 값**이라
검색어론 약하다. 부모 차원 키워드를 **맨 앞**에 생성한다:
- '제조업 취업자' → `['산업별 취업자', '취업자']`
- '석유류 물가 상승률' → `['품목성질별 소비자물가지수', '소비자물가지수']`
- '청년 실업률' → `['연령별 실업률', '실업률']`
모집단 한정어(청년·고령)는 검색어에서 빼고 분류축으로 처리.

### 1. 검색 + 후보 정렬
- 생성 키워드들(구체적인 것 먼저)로 `search_tables` → **순차 병합**(앞 키워드 우선, tbl_id dedup).
- **기간 미수록 표 제외**(구버전 ~2024 등은 최신 claim 을 못 담음).
- **조사명 티어 재정렬**: 0=국내 전국조사(경제활동인구조사·소비자물가조사·인구동향조사·
  장래인구추계·서비스업동향조사), 1=지역조사(지역별고용조사·시도·시군구·지방지표),
  2=국제기구(IMF/OECD/UN/World Bank/국제통계, `DT_2*`). 0순위를 위로.
- 상위 K(=8)개만 메타 판독 대상으로.

### 2. 메타 판독 — 후보 표의 구조 읽기
상위 후보 K개(기본 4)에 대해 `fetch_table_metadata`:
- **items**: `itm_id → 이름(단위)` — 무엇을 재는가 (예: `T30 취업자(천명)`, `T90 고용률(%)`).
- **axes**: 분류축별 `code → 이름` — 모집단/세부 분류 (예: 성별 `0=계`, 연령 `75=15-29세`, 산업 `10=제조업`).
- **periods**: 수록 주기(Y/M/Q) 와 형식.

### 3. 선택 — LLM이 표·항목·축 코드 고르기
후보 표들의 메타를 보여주고 한 번에 고른다(structured output):
- `tbl_id` — 가장 적합한 표 1개
- `itm_id` — 그 표의 항목 코드 (보기에 있는 것만)
- `axis_codes` — 각 분류축에서 고른 `{obj_id, code}` (모집단·세부분류 매핑)
- `abstain` — 적합한 표가 없으면 true

판단 규칙:
- **subject 최우선**(무엇을 측정), population/단위/기간은 보조.
- **모집단(population) → 분류축 값**: "청년"→연령 `15-29세`, "전체"→`계`. 못 맞추면 `계`(합계)로 폴백하되 그 사실을 표시(검증 신뢰도↓).
- **상승률/증감률 주제**: 항목에 "전년동월비(%)"가 있으면 그걸, 없으면 **지수 항목**을 고르고 §5에서 YoY를 직접 계산.
- 보기에 없는 코드를 **지어내지 않는다**.

### 4. 셀 조회 — objL 레벨 자동 ±조정 (숨은 C1축 주의)
`itmId` + 분류축 `objL`로 `statisticsParameterData.do` 호출.
- 빈 `objL` 전송은 error 21을 부른다 → 표 축 수만큼 `objL1..N=ALL`.
- **일부 표는 메타에 안 드러나는 숨은 C1축**을 가진다(예: `DT_1DA7E43S_NEW`는 메타상 축 2개지만 데이터는 C1(빈축)·C2(산업)·C3(취업시간)). objL 레벨 수가 안 맞으면:
  - error 20(부족)·21(초과)·**30(데이터 없음, 레벨 수 오류일 수 있음)** 모두 → 레벨 수 바꿔 재시도
  - 권장: `n_axes, n_axes+1, n_axes+2, n_axes-1` 순으로 시도(빈 응답도 다음 레벨 시도).
- 축을 일부만 골라도 동작하도록, 행 선택 시 **미지정 축이 '계/합계'인 행을 우선**한다.
- 응답 행에서 **`ITM_ID==itm_id` 이고 고른 축 값들이 `Ck_NM`(이름)으로 모두 존재**하는 행을 고른다.
  코드 위치(C1/C2…)가 표마다 달라 **이름 매칭이 위치 독립적이라 안전**하다.
  (이름이 모호하면 코드로 보강. 메모리 kosis-api-response-shape: 코드 == 비교.)

### 5. 변화율(YoY) 직접 계산 — 지수만 있는 표
claim이 "전년 동월/동기 대비 N% 변화"인데 고른 항목이 **지수(레벨)**면:
- 같은 좌표로 **전년 동기** 셀을 한 번 더 조회 → `(now/prev − 1) × 100 (%)`.
- 전년 동기 = 연도 4자리만 −1 (월/분기 뒤 2자리 유지).
- 항목 자체가 "전년동월비(%)" 등 **이미 변화율**이면 그대로 쓴다(재계산 금지).

### 6. 비교·판정 시 주의 (휴리스틱)
- **원계열 vs 계절조정**: 보도자료 수치는 보통 **원계열**. "계절조정" 표(예 `DT_1DA9003S`)는 값이 다르다 — 원계열 표를 우선.
  (실측: 2025.06 제조업 취업자 원계열 4,413.6 ✓ vs 계절조정 4,402.2 ✗)
- **반올림 허용오차**: KOSIS 천명/소수 1자리 ↔ 기사 "만 단위/소수". |주장−KOSIS| 가 반올림 한 자리 내면 일치로 본다(예 4,413.6→441만4천명, +2.24%→2.2%).
- **데이터 개정**: 게재 시점엔 맞았으나 이후 지수가 개정돼 현재 KOSIS와 어긋날 수 있다(예 소매판매 2024 기사 −2.2% vs 현재 −1.9%). 검증 불가가 아니라 "시점 차" — note로 남긴다.
