
## 4. 종합 관찰

### HCX-005 키워드 추출 품질
- 3건 모두 시스템 프롬프트의 5가지 원칙을 안정적으로 따랐음.
- 토큰 사용: 318~325 / latency 0.41~0.43s — 일관됨.
- 결정성: `temperature=0.0` 으로 출력 안정.

### KOSIS 검색의 성질
- **부분 문자열 매칭** 기반이라 표명에 키워드가 직접 포함되어야 결과가 깔끔.
- **띄어쓰기에 관용적** — 키워드 공백 제거가 매칭률을 떨어뜨리지 않음.
- "전국", "2023" 같은 한정어를 표명에 거의 쓰지 않음 → 키워드에서 제거하는 게 옳음.

### Claim → 통계표 매칭 설계에 대한 함의
- **케이스 1, 3**처럼 표명에 키워드가 직접 들어가는 경우엔 HCX-005 키워드 추출만으로 후보군이 잘 좁혀짐.
- **케이스 2**처럼 표명에 키워드 표현이 없는 경우엔 키워드 매칭만으로는 의도와 다른 표가 잡힘 → 임베딩 기반 유사도 검색(coarse→fine, `feature/table-embedding-search`) 으로 보완해야 함.
- 즉 **하이브리드** 가 맞음: 키워드 매칭(빠른 필터) + 임베딩 유사도(의미 매칭).

## 5. 재현 방법

```bash
# 프로젝트 루트에서
infisical run -- uv run python kosis/innnn/extract_best_keyword.py
```

키워드를 바꿔 실험하려면 [extract_best_keyword.py](extract_best_keyword.py) 의 `QUERIES` 리스트를 수정.

KOSIS 검색은 MCP 도구 호출:
```python
mcp__mcp-kosis__search_statistics(keyword="<추출된 키워드>", limit=10)
```
