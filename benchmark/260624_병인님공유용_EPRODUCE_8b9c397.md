## 3. 테스트 방법 — 측정 모드 (반드시 고정)

측정 도구를 단계마다 갈아끼우면 점수가 *모듈 품질*이 아니라 *측정법*을 반영한다. 역할별로 한 가지로 고정한다:

- **모듈 품질 = `frozen-독립`(격리)**: 독립 입력으로 `MasterSchema` 직접 구성 → 그 모듈만 실행 → 독립 gold 채점. 입력·gold 둘 다 독립이어야 함(파이프라인 캡처 입력 금지 = "캡처 얼린 cascade").
- **제품 결과 = `e2e`**: 신선 라이브 1~10단계 + 독립 최종 gold.
- **진단 = `cascade`**: 상류 라이브 전파. "어디서 깨지나"만 본다.

### 8b9c397 이 사용한 모드 = **e2e (전체) + 단계별 표(cascade/격리 혼합)**

`8b9c397` 의 대표 측정(`benchmark/e2e/leeaain_260623_13_8b9c397-dirty.md`)은 **e2e 전체 캡처 1회**로 funnel·분포·coverage 를 집계하고, 최종 verdict 를 독립 gold 와 대조했다. 단계별 표의 단계별 측정법은 아래로 고정:

| 단계 | 1차 지표 | 측정법 |
|---|---|---|
| 2 claim | 문장 F1 (P·R) · ctype | **격리(LLM)** |
| 3 normalize | value · period | cascade |
| 4 retrieve | Recall@10 · @1 · MRR | **value-recall** (정답 '표' 라벨 대신 figure 값이 후보표 셀에 실재하는지 KOSIS raw 확인) |
| 5 fetch | coverage · 셀값 | cascade |
| 6 rank | Top-1 | cascade |
| 7 metric | macro-F1 · recall[T/F/N] | cascade |
| 8 alignment | M-recall (M-precision·M-F1) | cascade |
| 9 verdict | exact-match | **격리(결정적)** |
| 10 explanation | 템플릿 accuracy(snapshot) | 격리 |

> 2·9 는 cascade 모드에서도 격리(LLM 유형분류·결정적 산식은 상류 노이즈와 무관하게 측정), 4 는 value-recall, 나머지는 cascade.

## 4. 하니스 (채점·저장 코드)

모든 코드는 `benchmark/` 바로 아래:

| 파일 | 역할 |
|---|---|
| `benchmark/scoring.py` | 단계별 채점기. `STAGE_SCORERS[N]` = 1차 지표 산출(P/R/F1·recall·accuracy·MRR…), 비율은 `wilson_ci`, 분류단계 전후비교는 `mcnemar` |
| `benchmark/reporting.py` | SSOT 로드(`load_ssot`)·저장(`save_result`)·`blank_sections`. `STAGE_IO` 로 저장 전 I/O 계약 검증(위반 시 `ContractError`) |
| `benchmark_aain/capture_pipeline_v2.py` | 213 SSOT → 파이프라인 1~10단계 실행, 단계별 스냅샷 캡처 |
| `benchmark_aain/eval_e2e_full.py` | 캡처 1개에서 [표A]단계별 + [표B]e2e funnel 산출·저장 |
| `benchmark/eval_stage2/3/5_frozen/6_frozen/7_frozen/8/9/10.py` | 단계별 격리 러너 |

**단계별 1차 지표(`STAGE_SCORERS`)**: 2=문장 P/R/F1+ctype · 3=value/period/compare accuracy · 4=Recall@1/3/10·MRR · 5=셀값 accuracy×coverage · 6=Top-1·Δvs RANK · 7=macro-F1+클래스 recall(+confusion) · 8=M-recall/precision/F1 · 9=exact-match · 10=템플릿 accuracy.

**I/O 계약**: 각 `benchmark/data/<N>/io.yml` 이 모듈 reads/writes + 테스트셋 record 필드를 명시. `save_result()` 가 `STAGE_IO` 로 기계 검사 → input 슬라이스/채점 필드 누락 시 저장 거부(wobble 방지).

## 5. e2e 재현 절차 (정확한 커맨드)

### Step 1 — 파이프라인 캡처 (213 기사, 1~10단계)

```bash
uv run x python benchmark_aain/capture_pipeline_v2.py \
  --out benchmark_aain/data/<YYMMDD>_capture_v2_<commit>.jsonl \
  --concurrency 8
```

- 입력: 고정 SSOT 213 (스크립트가 자동 로드).
- 발행일: 각 기사 `published_at` 을 base 로 상대시점 정규화(스크립트가 SSOT/웹서치로 주입).
- 스냅샷 지점 `SNAP_AFTER = {2,4,5,6,7,9}` → 각 단계 input 소스 + after9(최종 verdict).
- 출력 캡처(~15–20MB)는 **`.gitignore` 대상**(`benchmark_aain/data/*_capture_v2_*.jsonl`) = 로컬 전용·재생성용. **gold 아님, INPUT/예측 용도로만.**
- `8b9c397` 원본이 쓴 캡처 파일명 = `260623_capture_v2_run2.jsonl`.

### Step 2 — 채점 (2종 표 산출)

```bash
uv run python benchmark_aain/eval_e2e_full.py \
  benchmark_aain/data/<YYMMDD>_capture_v2_<commit>.jsonl
```

- 캡처 슬라이스 vs **독립 gold**(`benchmark/data/<N>/<N>_source_2.jsonl`) 대조. 재실행/LLM/KOSIS 호출 없음.
- 산출: **[표A] 단계별 지표** + **[표B] e2e funnel**, 자동 저장:
  - 단계별 → `benchmark/<N_module>/leeaain_<YYMMDD>_NN.jsonl`·`.md`
  - e2e → `benchmark/e2e/leeaain_<YYMMDD>_NN.jsonl`·`.md`

### (선택) 단계별 격리 측정


## 6. 출력 형식

- **파일명**: `<작성자>_<YYMMDD>_<NN>` (jsonl·md 동일 stem, 같은 폴더·작성자·날짜 순번). 무엇을 쟀는지는 폴더(단계)+md title.
- **`.jsonl`**: 한 줄 = 한 샘플, 실제 생성된 json 스키마(`input`/`output`/`gold` + 채점 필드).
- **`.md`**: title(`#`) 외 `###`만. 순서 = 개요 → 테스트 방법 → 성능 수치(표) → 분석 → 개선 전후 비교 → 한계·주의.

**[표B] e2e funnel** 고정 행(순서 고정): ① 전체 claim ② evidence_reach(셀 도달) ③ value_reach(값 도달) ④ coverage(T/F/M 판정) ⑤ gap(값 왔는데 NEI) ⑥ verdict 분포 `N·T·F·M`. + macro-F1·recall[T/F/N]·M-recall.

## 8. 주의·Caveat (재현 시 반드시 인지)

1. **LLM 비결정성**: stages 2·6·7·8 은 HCX 호출 → 같은 코드라도 run 마다 흔들림(예: 같은 8b9c397 두 번 run1/run2 에서 macro-F1 0.617↔0.596, recall[T] 0.308↔0.231). **단일 run 절대값이 아니라 CI/추세로 해석.** 비율 지표엔 `wilson_ci`, 분류 전후비교엔 `mcnemar`.
2. **cascade 점수는 모듈품질 단독 귀속 불가**(상류상태×LLM노이즈 혼입). 모듈 실력은 격리(frozen) 수치로 본다.
3. **gold 비순환 절대 준수**: 파이프라인 출력으로 gold 만들지 말 것. 캡처는 INPUT/예측으로만.
4. **캡처는 git 비추적**(20MB, regenerable). 팀원은 Step 1 로 직접 생성.
5. **`-dirty` 태그**: 8b9c397 측정 시 working tree 에 미커밋 하니스 코드가 있었음(파일명 `..._8b9c397-dirty`). 재현 시 하니스는 dev 의 `benchmark/` 를 쓰되 **데이터·gold·방법은 본 문서 고정값**을 따른다.
6. 모든 실행 `uv run x`(infisical). 비밀값(HCX/KOSIS_API_KEY) 출력 금지.
