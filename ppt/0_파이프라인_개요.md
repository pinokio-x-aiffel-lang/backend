# 파이프라인 전체 개요 (10단계)

> 통계 기반 가짜뉴스 검증 파이프라인 — 기사 한 편을 받아 KOSIS(국가통계포털) 공식 수치와 대조해 claim별 사실성을 판정한다.
> 조립·실행: `src/pipeline/runner.py` (`Pipeline.run`) · 각 단계 구현: `src/modules/` (1파일 1함수)
> 단계별 상세는 각각 `N_상세설명.md` 참조.

---

## 한눈에 보기

| 단계 | 이름 | 모듈 | 한 줄 요약 | LLM |
|:---:|---|---|---|:---:|
| **1** | 기사 내용 확인 | `load_article` | URL/본문 → 정제된 `Article`(본문·발행일·출처) | — |
| **2** | 클레임 추출 | `extract_statistical_claims` | 기사 → 검증 가능한 통계 주장 + 7+1유형 분류 | ✅ |
| **3** | 한국어 수사 산술로 변환 | `normalize_claim` | 한국어 수사·상대시점 → 표준 산술값(룰 우선·LLM 폴백) | △ |
| **4** | KOSIS 통계표 n개 찾기 | `retrieve_kosis_candidates` | subject → KOSIS 후보 통계표 상위 10개 검색 | △ |
| **5** | KOSIS 셀 값 조회 | `fetch_kosis_data` | 후보표에서 셀 좌표(항목×분류×시점) 찍어 실제값 조회 | △ |
| **6** | 증거 랭킹 | `rank_evidence` | 후보표 중 주제 가장 맞는 1위 표 선정(값 숨김) | ✅ |
| **7** | 통계 수치 비교 판단 | `calculate_metric` | 주장값 ↔ KOSIS값 비교 → T/F/N + 불일치 사유 | — |
| **8** | 정합성 판단 | `check_alignment` | T건의 해석 왜곡(framing)·메타 정합성 재판정 → M | ✅ |
| **9** | 종합 검증 결과 생성 | `decide_verdict` | claim별 확정 + 기사 단위 분포·지표 집계 | — |
| **10** | 설명 생성 | `generate_explanation` | 판정 → 한국어 설명(claim별 템플릿 + 종합 의견) | △ |

(✅=핵심 LLM, △=룰 우선 + LLM 폴백/일부, —=LLM 미사용 결정적)

## 데이터 흐름

```
[1] content(URL/본문) → article
[2] article → sentences, claims (claim_type 분류)
[3] claims.raw → claims.llm_value (수치·시점 표준화)
[4] claims.subject → analysis.candidates (후보표 10개)
[5] candidates → analysis.evidences (셀 실제값) + 증감형 기준시점
[6] evidences → 1위 표를 evidences[0]로 재정렬
[7] claim.value ↔ evidences[0] → verifications.claim_results[*].metric (T/F/N)
[8] T건 재판정 → T 유지 / M(해석 왜곡) / N(LLM 실패)
[9] metric.verdict 확정 + summary(verdict_counts, confidence, coverage)
[10] → claim_results[*].explanation + summary.overall_opinion
```

전 단계 시그니처는 `(master_schema) -> None` (제자리 변경). 실패 시 raise → runner가 `StepEvent(error)`로 변환·중단.

## 핵심 판정 코드 (Verdict)

| 코드 | 의미 | 생성 단계 |
|:---:|---|---|
| `T` | 일치 — 수치 + 해석 모두 정확 | 7 → 8 확인 |
| `F` | 불일치 — **수치 자체를 잘못 인용(확정 가짜)** | 7 |
| `M` | 수치 오도/왜곡 — 수치는 맞으나 해석 왜곡 | **8만** |
| `N` | 검증 불가 — 무증거·비교불가·판정 실패 | 4~8 어디서나 |

## 설계 철학 (발표 포인트)

1. **룰 베이스 우선, LLM은 최후의 폴백** — 결정성·재현성·비용·환각 통제 (3·4·5단계).
2. **정책/메커니즘 분리** — 좌표 매핑은 결정적으로 유지하고 "LLM 부를지(비용)"는 상위가 결정 (5단계).
3. **확증 편향 차단** — 표 선정 시 값을 숨기고 주제 적합도로만 (6단계).
4. **수치(F)와 해석(M) 분리** — "틀린 숫자"와 "맞는 숫자로 거짓말"을 다른 단계가 판정 (7·8단계).
5. **유효숫자 허용오차** — 기자의 반올림은 통과, 진짜 오류는 포착 (7단계).
6. **단일 라벨 강요 안 함** — 분포를 그대로 전달, 해석은 사용자에게 (9단계).
7. **낙인·환각 금지** — 중립 톤, 주어진 근거만 (10단계).

## 주요 병목·현황 (정직한 한계)

| 단계 | 현황 | 병목 원인 |
|---|---|---|
| 2 | 문장 추출 F1 **0.94** / claim_type acc 0.55 | 유형 경계 미세 |
| 4 | Recall@10 **0.35** | itmId 결정적 매칭(LLM 폴백 부재) — **전체 recall 핵심 병목** |
| 5 | coverage 0.52 / 셀값 acc 0.38 | 항목명-주제 의미 갭 |
| 7 | recall[F] 0.58 (개선) / recall[T] 낮음 | T-killer=증감(상류 2·3단계 미추출) |
| 8 | M-precision **0.93** / M-recall 0.35(격리 0.97) | 캐스케이드 상류 오류 전파 |

> 단계별 격리 성능은 높으나(예: 8단계 M-recall 격리 0.967), **캐스케이드(상류 오류 전파)**가 e2e 지표 상한을 누른다. → 상류(4·5단계 매칭) 개선이 최우선 레버리지.
