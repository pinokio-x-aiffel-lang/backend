# 7단계 — 통계 수치 비교 판단 (Calculate Metric / Numeric Layer)

> 코드: `src/modules/calculate_metric.py` · 수치 비교: `src/numeric/compare.py` (`compute_absolute`/`compute_change`)
> 값 파싱: `src/numeric/value.py` · 단위 환산: `src/numeric/units.py`
> 파이프라인 등록명: **"통계 수치 비교 판단"** (`src/pipeline/runner.py`, step 7)

---

## 1. 한 줄 정의

> **주장의 정규화된 수치(`llm_value`)와 KOSIS 공식값(증거)을 허용오차 내에서 비교해, 일치(T)/불일치(F)/판단보류(N)의 1차 판정과 불일치 사유(mismatch_type)를 계산하는 단계.**

이 단계는 **순수 수치 계산 레이어(Numeric Layer)** — LLM을 쓰지 않고 결정적으로 숫자만 비교한다.
"기자가 인용한 숫자가 통계청 공식값과 맞나?"를 푼다. 단, **"맞는데 해석이 왜곡됐나"**(M 판정)는 여기서 안 하고 8단계로 넘긴다.

---

## 2. 파이프라인 안에서의 위치

| 구분 | 내용 |
|---|---|
| **입력** | `claims[*].value.llm_value`(정규화 주장값) + `analysis[*].evidences`(KOSIS 셀값, 6단계가 1위 정렬) |
| **출력** | `master_schema.verifications` 생성 (`claim_results[*].metric: MetricResult`) |
| **다음 단계로** | 8단계가 T 케이스의 정합성 재판정, 9단계가 최종 확정 |
| **특징** | **LLM 미사용·완전 결정적** (재현 가능) |
| **실패 처리** | raise → runner가 `StepEvent(error)` |

## 3. 판정 코드 (Verdict) — 4종

| 코드 | 의미 | 설명 |
|:---:|---|---|
| `T` (TRUE) | 일치 | 수치 + 기사 해석 모두 정확 (→ 8단계가 해석 재판정) |
| `F` (FALSE) | 불일치 | **수치 자체를 잘못 인용 = 확정 가짜** (8단계 통과·9단계 직행) |
| `M` (NEEDS_REVIEW) | 수치 오도/왜곡 | 수치는 맞으나 기사 해석이 왜곡 — **8단계만 생성**(7단계는 M을 내지 않음) |
| `N` (NOT_ENOUGH_INFO) | 판단 보류 | 무증거·비교불가·검증대상 아님·정합성 판정 실패 |

> **7단계가 내는 것은 T/F/N 뿐.** M(해석 왜곡)은 "수치는 맞다(T)"가 전제라, T를 받은 케이스를 8단계가 원문 맥락으로 재판정해 M으로 떨어뜨린다.

---

## 4. claim_type별 처리 분기

| claim_type | 처리 | 비교 함수 | 결과 |
|---|---|---|---|
| `absolute` / `verifiable` | 단일 셀 직접 비교 | `compute_absolute` | T/F/N |
| `change_rate` | 두 시점 차(현재−기준) 비교 | `compute_change` | T/F/N |
| `ratio` / `distribution` / `comparison` | 그룹연산 (다중셀) | — | **N** (상류 미배선, Phase 2) |
| `metaphoric` / `none` | KOSIS 검증 대상 아님 | — | **N** |

- 단일 셀 직접비교가 가능한 유형은 `absolute`·`verifiable`·`change_rate` 뿐.
- `ratio`/`distribution`/`comparison`은 claim 그룹핑·다중셀 조회가 선행돼야 하는데 아직 미배선 → **N**으로 둠.

## 5. evidences[0] 기준 판정 로직 (`_decide_metric`)

표 선정은 6단계가 끝냈으므로 7단계는 **1위 표(`evidences[0]`)부터 비교**한다.

```
1위 적합 표(evidences[0])와 비교
   │
   ├─ T (일치) ────────────────→ T 확정 (→ 8단계 정합성 재판정)
   │
   └─ T 아님(F) → 나머지 표(evidences[1:])에 근사값(T 가능)이 있나?
        │
        ├─ 있음 → N(NEI) + needs_hitl=True (라벨러 판단)
        │         "1위 적합 표와 불일치하나 타 표에 근사값 존재"
        │
        └─ 없음 → F (1위 표 기준 거짓 = 확정 가짜)
```

- **무증거 / 비절대형 / 검증대상 아님** → N.
- `evidences[0]`을 항상 **대표 출처**로 둬서 값·출처 표기를 10단계 인용과 일치시킨다.
- 7단계의 유일한 HITL 트리거: **데이터 모호**(`DATA_AMBIGUITY`) — 1위 불일치 + 타 표 근사값.

> **모집단 폴백(전체값 대체)도 N으로 막지 않는다.** 전체값과 수치 비교해 T/F를 낸다.
> 이유: "요청 집단↔전체" 오도(모집단 M)는 8단계가 원문 맥락으로 판정해야 하는데, 7단계에서 N으로 죽이면 그 M 판정 기회가 사라진다. (폴백 사실은 note로 남겨 8단계 대상임을 표시)

## 6. 허용오차 — 유효숫자(반올림) 기반 (`tolerance_abs`)

주장 표기의 **마지막 유효자리 ±0.5**를 허용오차로 자동 계산한다. (끝자리 0은 정밀도로 안 침)

| 주장 표기 | 허용오차(±) | 의미 |
|---|---|---|
| `"3.5"` | 0.05 | 소수 1자리 |
| `"0.75"` | 0.005 | 소수 2자리 |
| `"3.0"` | 0.5 | `"3%대"`(3.0)가 3.1%를 허용 |
| `"5"` | 0.5 | 정수 |
| `"238300"` | 50 | 끝 0이 2개 → 백의 자리 반올림 |
| `"238000"` | 500 | |
| `"230000"` | 5000 | |

> **왜 유효숫자 기반?** 기자는 `"약 238만 명"`처럼 반올림해 쓴다. 통계청 원값 `238,317`과 `238,300`은 같은 주장이다. 표기 정밀도만큼만 허용해, 반올림은 통과시키되 진짜 오류는 잡는다.

## 7. 불일치 사유 분류 (mismatch_type) — 9종

| 코드 | 의미 | 담당 단계 |
|---|---|:---:|
| `magnitude` | 값 크기 차이(허용오차 크게 초과) | **7** |
| `rounding` | 허용오차 소폭 초과(반올림 경계, ≤2×tol) | **7** |
| `direction` | 증감 방향 차이(부호 반대 — 증가↔감소) | **7** |
| `unit` | 단위 불일치·비교불가 | 7/8 |
| `period` | 기간(연도) 불일치 | 7/8 |
| `population` | 모집단 불일치(전체↔청년 등) | 8 |
| `subject` | 측정 주제 불일치 | 8 |
| `aggregation` | 집계 방식 불일치(평균↔합계) | 8 |
| `framing` | 해석 비약·프레이밍(사실문장 A→기자해석 B 왜곡) | 8 |

7단계가 F를 낼 때 분류: **연도부터 보고**(`claim 연도 ≠ KOSIS 연도` → `period`), 아니면 초과 폭으로(`≤2×tol` → `rounding`, 그 이상 → `magnitude`).

## 8. compute_absolute — 단일 시점 직접 비교

1. 주장값 파싱(`parse_claim_value`) → 스칼라/범위/부호/비교불가 구분.
2. **단위 정렬**(`align_value`): KOSIS 단위 → claim 단위 환산.
   - 단위 비교불가(`incompatible`/`unknown_unit`/`non_absolute`) → `N` + `mismatch=unit`.
   - **KOSIS 단위 메타가 비어있으면**(누락) claim 단위로 가정 비교(`assumed_same`) — 값이 정확해도 N으로 죽던 문제 해결.
3. **범위/부등 표기**(`50~100`, `>=89`, `<75`)는 **포함 비교**: 경계 안이면 T, 밖이면 F(`magnitude`).
4. 스칼라면 `|주장−KOSIS| ≤ tol` → T, 아니면 F + 사유 분류.

---

## 9. compute_change — 증감(change_rate) 비교

5단계가 같은 셀 좌표로 **현재(period)·기준(compare_period) 두 시점**을 조회해 `evidence.value`/`compare_value`에 담아둔다.

| claim.unit | 계산식 |
|---|---|
| `%`(증감률) | `(신−구)/구 × 100` |
| 그 외(명·원·%p 등) | `절대 증감 = 신−구` (단위 환산, %p는 변화량이라 환산 제외) |

- 두 시점 중 하나라도 없으면 → `N`("증감 비교 불가").
- 허용오차: 유효숫자 절대오차 **또는 상대오차 ≤2%**(`_CHANGE_REL_TOL`) — 큰 반올림 증감값(예: `216000`)이 ±0.5로 항상 F 되는 걸 방지.
- 불일치 사유: **크기는 맞고 부호만 반대** → `direction`(증가↔감소 오류), 아니면 `magnitude`.

> ⚠️ **증감형이 현재 가장 약한 부분(T-killer #1).** recall[T]가 낮은 원인은 7단계가 아니라 상류 — 2단계 비교기준 미추출(115/185), 3단계 compare_period 오정규화(24건). (벤치 노트 기록)

## 11. 성능 (벤치마크 `benchmark/7_metric/`)

#2(population fallback NEI 해제)·#3(range 포함비교) 개선 전후 (after6 동결 캡처):

| 지표 | before | after |
|---|---|---|
| macro-F1 | 0.424 | **0.476** |
| recall[T] | 0.051 (2/39) | 0.051 (2/39) |
| recall[F] | 0.389 (14/36) | **0.583** (21/36) |
| recall[N] | 1.000 (51/51) | 1.000 (51/51) |

**해석**
- **#3 범위/부등 포함비교** → F +2. **#2 모집단 폴백 NEI 해제** → 전체값과 T/F 비교(F +5), 모집단 M은 8단계로.
- **recall[T]가 안 오르는 이유:** 남은 T-killer가 증감(상류 미추출)이라 7단계만으론 못 고침.
- recall[N] 무손상 — 폴백 해제가 N을 오염시키지 않음.

## 12. 한 줄 정리

> 7단계는 **"주장 수치 ↔ KOSIS 공식값"** 결정적 비교기다.
> 핵심은 ① **유효숫자 허용오차**(반올림 통과·오류 포착), ② **1위 표 우선 + 타 표 근사값 시 HITL**,
> ③ **F=확정 가짜(수치 오인용)**, ④ **모집단 폴백을 N으로 안 죽이고 8단계 M 판정으로 넘김**이다.
> M(해석 왜곡)은 7단계가 아니라 8단계의 몫이다.
