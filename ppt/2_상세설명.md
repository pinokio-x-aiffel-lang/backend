# 2단계 — 통계 주장 추출 (Extract Statistical Claims)

> 코드: `src/modules/extract_statistical_claims.py` · 전처리: `src/modules/preprocess_article.py`
> 프롬프트: `EXTRACT_CLAIMS_SYSTEM` / `EXTRACT_CLAIMS_USER` (`src/prompts/prompts.py`)
> 파이프라인 등록명: **"클레임 추출"** (`src/pipeline/runner.py`, step 2)

---

## 1. 한 줄 정의

> **기사 본문에서 "검증 가능한 수치 기반 통계 주장(claim)"만 골라내고, 각 주장을 7+1가지 유형으로 분류하여 구조화된 데이터로 만드는 단계.**

기사는 자연어 문장 덩어리다. 이 단계가 끝나면, 기사 안의 모든 수치 주장이
- **무엇을(subject)**,
- **얼마라고(value)**,
- **언제 기준으로(period)**,
- **누구를 대상으로(population)**,
- **어떤 출처를 인용해(cited_source)**,
- **어떤 검증 연산이 필요한 유형인지(claim_type)**

로 쪼개진 표(=`list[Claim]`)가 된다. 이후 3~9단계는 이 표를 입력으로 KOSIS 통계와 대조한다.

---

## 2. 파이프라인 안에서의 위치

| 구분 | 내용 |
|---|---|
| **입력** | `master_schema.article` — 1단계(기사 적재)에서 채워진 기사 본문 |
| **출력 1** | `master_schema.sentences` : `list[str]` — 필터·원자화된 검증 단위 문장들 |
| **출력 2** | `master_schema.claims` : `list[Claim]` — 추출된 주장들 (분류불가 `NONE` 포함) |
| **다음 단계로** | 3단계(정규화)가 `claims`를 받아 한국어 수사 표현을 산술값으로 변환 |
| **실패 시** | `ExtractStatisticalClaimsError` raise → runner가 `StepEvent(error)`로 변환·중단 |

> ⚠️ `claim_type == NONE`(분류 불가) 항목도 **버리지 않고** `claims`에 포함한다.
> 검증 대상에서 제외할지는 **분기(하류) 모듈의 책임**이다. 이 단계는 "추출과 분류"만 한다.

---

## 3. 내부 처리 흐름 (3단계)

이 단계는 내부적으로 **[a] 후보 필터 → [b] 원자 문장화 → [c] LLM 추출**의 3단계로 동작한다.

```
기사 본문
  │
  ├─[a] 후보 필터 (규칙, LLM 미사용)
  │     · 문서 정제(HTML·기자명·저작권·장식기호 제거) + 문장 분리
  │     · 정규식으로 "수치 후보 문장"만 선별
  │     · 후보가 0개면 → claims=[], sentences=[] 로 즉시 종료 (LLM 호출 안 함)
  │
  ├─[b] 원자 문장화 (LLM: HCX-005)
  │     · 복합 문장 1개 → 검증 단위 원자 문장 N개로 분해
  │     · "1.9%에서 1.5%로 하락" → ["1.9%였다", "1.5%로 하락했다"]
  │     · 20문장씩 배치, 실패 시 원문 그대로 (fallback)
  │
  └─[c] 통계 주장 추출 (LLM: HCX-007)
        · 원자 문장에서 claim 추출 + claim_type 분류 + 필드 채움
        · HCX Structured Outputs(JSON 스키마)로 형식 강제
        · 최대 5개 claim 추출
```

### [a] 후보 필터 — 왜 정규식부터 거치나
LLM 호출 전에 "수치가 들어있을 법한 문장"만 남겨 **토큰 낭비를 줄인다.**
설계 원칙은 **재현율 우선(favor recall)** — 과포함은 토큰 낭비에 그치지만, 누락은 claim 유실로 직결되기 때문.

선별 정규식(`_RE_STAT_CANDIDATE`)이 잡는 패턴:

| 분류 | 잡는 표현 |
|---|---|
| 아라비아 숫자 | `0~9`, 전각 숫자 `０~９` |
| 퍼센트·포인트 | `%`, `퍼센트`, `포인트` |
| 비유적 수치 | `절반`, `반토막`, `갑절`, `곱절` |
| 배수 표현 | `두/세/네/다섯/여섯/일곱/여덟/아홉/열/스무/몇` + `배` |

문서 정제(`_clean_document`)가 제거하는 노이즈: HTML 태그·엔티티, 이메일, `OOO 기자`, 저작권 문구(`ⓒ`, `무단전재`, `재배포 금지`), 장식 기호(`◆■▶●★` 등).

### [b] 원자 문장화 — 1문장 1사실 만들기
한 문장에 검증 가능한 수치가 2개 이상이면 반드시 분리한다. (모델: HCX-005)

| 패턴 | 입력 | 출력 |
|---|---|---|
| X에서 Y로 | `실업률이 1.9%에서 1.5%로 하락했다` | `실업률은 1.9%였다` / `실업률은 1.5%로 하락했다` |
| 괄호 안 이전값 | `수출액이 5,231억 달러(전년 4,821억 달러)` | `수출액은 5,231억 달러였다` / `전년 수출액은 4,821억 달러였다` |
| 절대값+변화율 | `GDP 성장률이 2.1%로, 전년 대비 0.4%p 하락` | `GDP 성장률은 2.1%였다` / `전년 대비 0.4%p 하락했다` |
| 여러 대상 열거 | `남성 실업률은 3.2%, 여성은 2.8%` | `남성 실업률은 3.2%였다` / `여성 실업률은 2.8%였다` |
| 다중 시점 열거 | `2021년 5.0%, 2022년 4.5%로 하락` | `2021년 실업률은 5.0%였다` / `2022년 실업률은 4.5%였다` |
| 비교형 | `서울 실업률(3.2%)이 부산(2.1%)보다 높다` | `서울 실업률은 3.2%였다` / `부산 실업률은 2.1%였다` |

분해 규칙: 주어를 명시해 문맥 없이도 이해되게 / 시점·단위·출처 표기는 절대 삭제 금지.

### [c] 통계 주장 추출 — 분류와 구조화
원자 문장 목록을 LLM(HCX-007)에 넣어 claim을 뽑고, 각 claim에 9개 필드를 채운다.
HCX Structured Outputs(JSON 스키마)로 출력 형식을 강제한다.

## 4. 무엇을 추출하고, 무엇을 버리는가

### ✅ 추출 대상
- 통계청·연구기관·기업 실적 등 **외부 출처에서 나온 수치**
- **시점이 명시된** 경제·사회 지표

### ❌ 추출 제외

| 제외 대상 | 예시 |
|---|---|
| 전망·예측·추정치 | "내년에는 3% 성장할 전망" |
| 정성적·비유적 표현 | (수치 없는 주관 서술) |
| 제품 구성·사양 | "배터리 5000mAh, 카메라 3개" |
| 단순 열거 | "~종", "~개" 포함 나열 |
| 순위 | "세계 7위" |
| 연속·추세·기록 문구 **자체** | "두 달 연속 상승", "10개월째 증가세", "N년 만에 최대" |

> **추세 문구의 예외 처리:** 추세 문구 자체는 claim이 아니지만, 그 안에 **개별 시점의 수치가 병기**되어 있으면 그 수치들은 각각 별도 claim으로 추출한다.
> 예) `1월(7.3%)에 이어 두 달 연속 5% 이상 상승` → "두 달 연속"은 제외, **1월 7.3%**와 **당월 상승률**은 각각 claim.

## 5. claim_type — 7+1가지 분류 (이 단계의 핵심)

각 claim은 **검증에 필요한 연산 형태**에 따라 분류된다. 겹칠 경우 **우선순위가 높은 유형**으로 결정한다.
(enum 정의: `ClaimType`, `src/schemas/runtime.py`)

| 우선순위 | 코드 | 한글 의미 | 검증 연산 | 예시 |
|:---:|---|---|---|---|
| 1 | `absolute` | 절대값 | 단일 시점 값 직접 비교 | "2023년 실업률은 5.9%였다" |
| 2 | `change_rate` | 증감률 | (신−구)/구 | "전년 대비 2.1%p 하락했다" |
| 3 | `ratio` | 비율 (A/B) | A ÷ B | "청년 실업률은 전체의 2배에 달한다" |
| 4 | `distribution` | 분포(구성비·점유율) | 부분 ÷ 전체 | "여성이 전체의 51%를 차지했다" |
| 5 | `comparison` | 그룹 간 비교 | 그룹 간 부등식 | "서울이 부산보다 3배 높았다" |
| 6 | `metaphoric` | 비유비교 | **KOSIS 검증 불가** (수치로 표현되나 통계표 대조 불능) | "물가가 2배 뛰었다는 체감" |
| 7 | `verifiable` | 검증가능(기타) | 위 6가지 미해당 + KOSIS 검증 가능 (**최후순위**) | 통계표로 확인 가능한 기타 수치 |
| — | `none` | 분류 불가 | 검증 불가 — 분기에서 제외 | 검증 불가 주관적 표현 등 |

**우선순위 순서:** `ABSOLUTE > CHANGE_RATE > RATIO > DISTRIBUTION > COMPARISON > METAPHORIC > VERIFIABLE`
→ 위에서부터 판단하여 **가장 먼저 해당하는 유형**을 채택. `verifiable`은 "다른 데 안 걸릴 때만" 쓰는 폴백.

## 6. 추출하는 필드 (Claim 구조)

claim 1건마다 아래 필드가 채워진다. (`Claim`, `src/schemas/runtime.py`)
LLM 스키마(`CLAIMS_SCHEMA`)에서 **필수 4개**(`claim_type`/`subject`/`value_raw`/`period_raw`)만 강제하고, 나머지는 파서가 `.get()`으로 방어(없으면 `'불명'`/`None`)한다.

| 필드 | 필수 | 의미 | 예시 |
|---|:---:|---|---|
| `sentence` | | 추출 원문 문장 | "2023년 실업률은 5.9%였다" |
| `claim_type` | ✅ | 위 7+1 분류 | `absolute` |
| `subject` | ✅ | **측정 주제만** (국가/지역 한정어 제외, 산업/부문 한정어 유지) | "실업률", "제조업 취업자 수" |
| `value_raw` | ✅ | **수치 1개** 원문 (증감이면 방향어 포함) | "5.9%", "8만3000명 줄었다" |
| `unit` | | 측정 단위만 | `%`, `%p`, `명`, `원`, `억원` |
| `period_raw` | ✅ | **시점 1개** 원문 | "2023년", "지난달" |
| `period_type` | | 주기 코드 (아래 표) | `Y` |
| `compare_period_raw` | | 비교 기준 시점 (증감이면 거의 필수) | "전년 동월", "1년 전" |
| `population` | | 대상 집단 (없으면 출처·맥락 추론) | "대한민국", "청년층" |
| `cited_source` | | 인용 출처 | "통계청", "한국은행" |

> ⚠️ **필수를 4개로 제한한 이유:** 10개 전부 필수로 강제하면, 다중 claim 문장에서 HCX가
> `{"claims": []}`로 후퇴하는 현상이 결정적으로 재현됨(260612 분리 실험 3회). 그래서 핵심 4개만 강제.

### period_type — 주기 코드

| 코드 | 의미 |
|:---:|---|
| `Y` | 연간 (Year) |
| `M` | 월간 (Month) |
| `Q` | 분기 (Quarter) |
| `S` | 반기 (Semiannual) |
| `D` | 일간 (Day) |

(유효하지 않은 값이 오면 기본 `Y`로 보정.)

## 7. 정밀 추출 규칙 (오추출 방지 장치)

분류만큼 중요한 것이 "값을 어떻게 쪼개 담느냐"다. 아래 규칙들이 하류 검증의 정확도를 좌우한다.

### 규칙 ① 1 claim = 1 수치 · 1 시점 (합본 금지)
한 claim의 `value_raw`엔 수치 1개, `period_raw`엔 시점 1개만.
- ❌ `9월(-0.4%)·10월(-0.2%)·11월(-0.4%)` → "-0.4%/-0.2%/-0.4%" 합본 1개
- ✅ 시점별로 3개 claim으로 분리

### 규칙 ② value_raw에 방향어 포함 (증감 주장)
`change_rate`면 증감 방향어(증가/감소/늘었다/줄었다/올라/내려 등)를 **반드시** `value_raw`에 포함.
- ✅ `"8만3000명 줄었다"` / ❌ `"8만3000명"`
- `change_rate`의 value는 **증감폭**이지 절대 수준값이 아니다.

### 규칙 ③ 절대값 + 증감폭은 각각 별도 claim
- 입력: `"취업자는 2858만9000명으로 19만3000명 증가"`
- 출력: `absolute(value="2858만9000명")` + `change_rate(value="19만3000명 증가")`

### 규칙 ④ compare_period(비교 기준 시점) — 증감이면 거의 필수
수치가 무엇과 비교됐는지(증감의 기준 시점)를 원문 그대로 추출.

| 원문 표현 | compare_period_raw |
|---|---|
| 전년 동월 대비 | "전년 동월" |
| 전월 대비 | "전월" |
| 전분기 대비 | "전분기" |
| 전년 대비 / 전년보다 | "전년" |
| 작년 4월보다 | "작년 4월" |
| 1년 전보다 | "1년 전" |
| 2013년 말 대비 | "2013년 말" |

> **혼동 금지:** 비교 기준(compare_period)과 주 시점(period)을 절대 섞지 말 것.
> 예) `"지난달 취업자는 작년 4월보다 19만명 증가"` → `period_raw="지난달"`, `compare_period_raw="작년 4월"`.
> 비교 표현이 정말 없을 때만(예: "26만명 증가") 빈 문자열.

### 규칙 ⑤ subject ↔ population 분리
`subject`엔 **측정 주제만**, 대상 집단 한정어는 `population`으로.

| 구분 | 처리 | 예시 |
|---|---|---|
| 국가·지역 한정어 | subject에서 빼고 → population | "한국의 경제성장률" → subject=`경제성장률`, population=`대한민국` |
| 산업·부문·품목 한정어 | subject에 **유지** (측정 주제의 일부) | "제조업 취업자 수" → subject=`제조업 취업자 수` (○) / `취업자 수` (×) |
| 연령·성별·지역 한정어 | population으로 | "청년층 고용률" → subject=`고용률`, population=`청년층` |

- `population`은 명시가 없으면 **출처·맥락으로 추론**: 통계청·국가데이터처·정부부처·한국은행 발표의 국내 지표면 → `"대한민국"`. 추론 근거가 전혀 없을 때만 `"불명"`.
- 표준형 사용: "한국 전체/전국" 대신 → `"대한민국"`.

## 8. 사용 모델·파라미터

| 내부 단계 | 모델 | max_tokens | temperature | 비고 |
|---|---|---:|:---:|---|
| [b] 원자 문장화 | `HCX-005` | 1024 | (기본) | 20문장 배치, 실패 시 fallback |
| [c] 통계 주장 추출 | `HCX-007` | 2048 | **0.0** | 결정적 추출·평가 재현성 위해 0 고정 |

- 모든 LLM 호출은 `LlmCaller` 경유(`traced_chat`), 파라미터는 `ModelPreset`(`src/llm/model_presets.py`)에서만 가져옴.
- 추출 출력 형식은 HCX **Structured Outputs**(JSON 스키마 `CLAIMS_SCHEMA`)로 강제.
- 한 번 호출당 **최대 5개** claim 추출.

|---|---|---|
| 문장 Precision | **0.967** (58/60) | [0.886, 0.991] |
| 문장 Recall | **0.921** (58/63) | [0.827, 0.966] |
| 문장 **F1** | **0.943** | — |
| claim_type accuracy | 0.551 (27/49) | [0.413, 0.681] |
| claim_type macro-F1 | 0.240 | — |

**해석**
- **문장 단위 추출(claim 여부)**은 F1 0.94로 매우 안정적. Precision은 음성이 hard-negative(어려운 비-claim)만이라 **보수적으로 측정된 하한**.
- **claim_type 분류 정확도(0.55)**는 추출 성공 양성 행만 분모로 한 값으로, **개선 여지가 큰 지점**(7+1 유형 간 경계가 미세).

## 10. 한 줄 정리

> 2단계는 **"기사의 자연어 수치 문장 → 검증 가능한 구조화된 통계 주장 표"** 변환기다.
> 핵심 산출물은 ① **claim 여부 선별(F1 0.94)**, ② **7+1 유형 분류**, ③ **수치/시점/주체/대상/출처의 정밀 분해**이며,
> 이후 모든 KOSIS 대조 단계(3~9)는 이 표를 입력으로 삼는다.

### 전체 케이스 표 (빠짐없이)

2단계가 처리하는 모든 케이스를 분기별로 정리. 핵심은 **표 A(claim_type 8가지 분류)**이고, B~G는 그 분류를 만들 때 적용되는 **추출·필드 규칙 분기**다.

#### 표 A. claim_type 분류 — 8가지 (★ 메인 분기)

우선순위 순으로 위에서부터 판단, **가장 먼저 해당하는 유형** 채택. 겹치면 높은 우선순위.

| 우선 | 코드 | 한글 | 정의 | 예시 | 검증 연산(7단계) | 현재 검증? |
|:--:|---|---|---|---|---|:--:|
| 1 | `absolute` | 절대값 | 단일 시점 절대값 | "2023년 실업률 5.9%" | 단일 셀 직접비교 | ✅ |
| 2 | `change_rate` | 증감률 | 전년대비 등 증감 | "전년 대비 2.1%p 하락" | 2시점 차 (신−구) | ✅ |
| 3 | `ratio` | 비율(A/B) | A가 B의 몇 배/몇 분의 | "청년 실업률은 전체의 2배" | 그룹연산(다중셀) | 🔴 NEI (미배선) |
| 4 | `distribution` | 분포 | 구성비·점유율 | "여성이 전체의 51% 차지" | 그룹연산(부분/전체) | 🔴 NEI (미배선) |
| 5 | `comparison` | 비교 | 그룹 간 부등식 | "서울이 부산보다 3배 높음" | 그룹연산(A vs B) | 🔴 NEI (미배선) |
| 6 | `metaphoric` | 비유비교 | 수치로 표현되나 KOSIS 검증 불가 | "물가가 2배 뛰었다는 체감" | — | 🔴 NEI (대상 아님) |
| 7 | `verifiable` | 검증가능(기타) | 위 6개 미해당 + KOSIS 검증 가능 (최후순위) | 통계표로 확인 가능한 기타 수치 | 단일 셀 직접비교 | ✅ |
| — | `none` | 분류불가 | 7가지 모두 미해당 | 검증 불가 주관 표현 | — | 🔴 분기서 제외 |

#### 표 B. 추출 대상 vs 제외

| 구분 | 케이스 | 비고 |
|---|---|---|
| ✅ **추출** | 통계청·연구기관·기업실적 등 **외부 출처 수치** | |
| ✅ **추출** | **시점 명시된** 경제·사회 지표 | |
| ❌ 제외 | 전망·예측·추정치 | "내년 3% 성장 전망" |
| ❌ 제외 | 정성적·비유적 표현 | |
| ❌ 제외 | 제품 구성·사양 | |
| ❌ 제외 | 단순 열거 (`~종`, `~개`) | |
| ❌ 제외 | 순위 | "세계 7위" |
| ❌ 제외 | 연속·추세·기록 문구 **자체** | "두 달 연속 상승", "10개월째 증가세", "N년 만에 최대" |
| ⚠️ **예외 분기** | 추세 문구에 **개별 시점 수치 병기** 시 → 그 수치는 각각 claim | "1월(7.3%)에 이어 두 달 연속" → "두 달 연속"=제외, **1월 7.3%**=claim |

#### 표 D. value_raw 처리 분기 (수치 담는 규칙)

| 분기 | 규칙 | 예시 |
|---|---|---|
| **합본 금지** | 1 claim = 수치 1개·시점 1개 | "9월(-0.4%)·10월(-0.2%)" → **시점별 분리** |
| **증감 방향어** | change_rate면 방향어(증가/감소/늘었다/줄었다/올라/내려) **반드시 포함** | "8만3000명 줄었다"(○) / "8만3000명"(×) |
| **절대값+증감폭 분리** | 한 문장에 둘 다면 **각각 별도 claim** | "2858만9000명으로 19만3000명 증가" → `absolute(2858만9000명)` + `change_rate(19만3000명 증가)` |
| **증감폭 의미** | change_rate의 value는 **증감폭**, 절대 수준값 아님 | |

#### 표 E. compare_period_raw 분기 (비교 기준 시점) — change_rate면 거의 필수

| 원문 표현 | → 추출값 |
|---|---|
| 전년 동월 대비 | "전년 동월" |
| 전월 대비 | "전월" |
| 전분기 대비 | "전분기" |
