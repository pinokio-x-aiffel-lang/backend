# 10단계 — 설명 생성 (Generate Explanation)

> 코드: `src/modules/generate_explanation.py`
> 프롬프트: `GENERATE_OPINION_*` (`src/prompts/prompts.py`)
> 파이프라인 등록명: **"설명 생성"** (`src/pipeline/runner.py`, step 10)

---

## 1. 한 줄 정의

> **판정 결과(T/F/M/N)를 사람이 읽을 한국어 설명으로 바꾸는 마지막 단계 — claim별 한 줄 설명(결정적 템플릿) + 기사 단위 종합 의견 한 문단(LLM).**

지금까지는 전부 내부 데이터(코드·숫자·enum)였다. 10단계는 그걸 **독자에게 보여줄 자연어**로 번역한다.
두 종류의 출력을 만든다: ① **claim별 설명**(정해진 템플릿, 결정적), ② **기사 전체 종합 의견**(LLM 생성, 실패 시 템플릿 폴백).

---

## 2. 파이프라인 안에서의 위치

| 구분 | 내용 |
|---|---|
| **입력** | `verifications`(9단계 판정 결과) + `claims`(subject·unit·period 참조) |
| **출력 1** | `claim_results[*].explanation` — claim별 한국어 템플릿 설명 (결정적) |
| **출력 2** | `verifications.summary.overall_opinion` — 기사 단위 LLM 종합 의견 한 문단 |
| **특징** | claim 설명은 **결정적**, 종합 의견만 LLM(실패해도 run 중단 안 함) |

---

## 3. ① claim별 템플릿 설명 (결정적, `_build_explanation`)

verdict별로 정해진 한국어 문장을 생성한다. (LLM 미사용)

| verdict | 설명 템플릿 (예) |
|:---:|---|
| `T` | "기사의 {기간}{주제} {값}은 KOSIS 공식 수치와 **일치합니다**. (출처: {표명})" |
| `F` | "기사의 {기간}{주제} {값}은 KOSIS 공식 수치({KOSIS값})와 **다릅니다**. 불일치 유형: {mismatch}." |
| `M` | "기사의 {기간}{주제} {값}은 KOSIS 공식 수치({KOSIS값})와 **부분적으로 일치합니다**." |
| `N` | "{기간}{주제}에 대한 KOSIS 공식 통계를 찾지 못해 **검증할 수 없습니다**." |

### 한국어 자연스러움 처리
- **조사 자동 선택**(`_eun_neun`): 마지막 음절 받침 유무로 `은/는` 결정.
- **기간 한국어화**(`_format_period`): `2024-03`→`2024년 3월`, `2024-Q1`→`2024년 1분기`, `2024-H1`→`2024년 상반기`. 정규화 형식(`YYYY-MM`)과 KOSIS PRD_DE 형식(`YYYYMM`) 모두 처리.

---

## 4. ② 기사 단위 종합 의견 (LLM, `_generate_opinion`)

claim별 판정을 요약해 LLM(HCX-005)에 주고 **한 문단(3~5문장)** 총평을 생성.

### LLM 입력 — claim 요약 한 줄 (`_claim_line`)
verdict 라벨을 맨 앞에 두고, 수치 일치 여부를 `=`/`≠`로 못 박는다:

| verdict | 요약 형태 |
|:---:|---|
| `T` | `[일치] 2024년 근로시간: 기사 38.8시간 = 공식 38.8시간 (수치 일치)` |
| `F` | `[불일치] …: 기사 X ≠ 공식 Y (수치 불일치, {사유})` |
| `M` | `[검토필요] …: 기사 X = 공식 Y (수치는 일치하나 {사유}로 표현 오도)` |
| `N` | `[검증불가] …: 기사 X, 공식 통계 없음 (검증 불가)` |

> ⚠️ **M과 F를 절대 섞지 않게** 명시: M은 "수치는 일치(=)하나 해석 오도", F는 "수치 자체가 틀림(≠)". jargon(영문 mismatch_type)은 한국어 사유로 변환해 노출.

### 프롬프트 규칙 (요지)
1. **각 주장의 판정 라벨을 그대로 따른다** (라벨과 다르게 분류 금지).
   - `[불일치]`·`[검토필요]`를 "정확하다/맞다"고 쓰지 마라.
   - `[검토필요]`는 수치 일치 — "수치가 다르다"고 쓰지 말고 해석·표현 문제로만.
   - `[검증불가]`는 기사 오류가 아니라 통계 부재 — "오류/틀림"으로 묶지 마라.
2. 판정 분포를 반영해 전반적 신뢰성 평가.
3. 주어진 결과만 근거 — **새 사실·수치 지어내기 금지**.
4. 중립적·객관적 톤 — **"가짜뉴스" 같은 단정적 낙인 금지**.
5. 한국어 3~5문장 한 문단, 머리말·목록·마크다운 없이 본문만.

### 폴백 (`_fallback_opinion`)
LLM 실패/미사용 시 **결정적 템플릿 총평**: 분포 문장 + verdict 기반 한 문장(F 있으면 주의, M 있으면 해석 검토, 전부 T면 일치 확인 등). → 전체 run은 중단하지 않음.

## 6. 성능 (벤치마크 `benchmark/10_explanation/leeaain_260619_01.md`)

| 지표 | 값 | 95% CI |
|---|---|---|
| 템플릿 accuracy(snapshot) | **1.000** (407/407) | [0.991, 1.000] |
| opinion: 분포 반영 | 0.981 (209/213) | [0.953, 0.993] |
| opinion: verdict 모순 없음 | **1.000** (213/213) | [0.982, 1.000] |
| opinion: 환각 없음 | **1.000** (213/213) | [0.982, 1.000] |

**해석**
- 템플릿은 결정적이라 ~1.0(스냅샷 회귀 정상).
- 의미 있는 품질 지표는 **opinion 루브릭**(LLM-심판 3기준: 분포 반영·verdict 모순 없음·환각 없음).
- **verdict 모순 없음·환각 없음 모두 1.0** — 프롬프트의 "라벨 그대로 따르기/지어내기 금지"가 잘 지켜짐.

---

## 7. 한 줄 정리

> 10단계는 **"판정 코드 → 사람이 읽을 한국어"** 번역기다.
> 핵심은 ① **claim별 결정적 템플릿 설명**(조사·기간 한국어화), ② **기사 단위 LLM 종합 의견**(M/F/N 구분 엄수·낙인 금지·환각 금지),
> ③ **LLM 실패 시 템플릿 폴백**으로 항상 결과를 낸다. 파이프라인의 최종 사용자 출력단이다.
