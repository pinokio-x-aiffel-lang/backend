# 9단계 — 종합 분석·검증 결과 생성 (Decide Verdict)

> 코드: `src/modules/decide_verdict.py`
> 파이프라인 등록명: **"종합 분석·검증 결과 생성"** (`src/pipeline/runner.py`, step 9)

---

## 1. 한 줄 정의

> **7·8단계가 만들고 보정한 claim별 판정(metric.verdict)을 최종 확정하고, 기사 단위로 verdict 분포와 두 지표(사실성·검증률)를 집계하는 단계.**

지금까지는 claim 하나하나를 따로 판정했다. 9단계는 그걸 **기사 전체 관점으로 종합**한다.
단, **단일 종합 라벨("이 기사는 가짜다")은 내지 않는다** — `{T:.., F:.., M:.., N:..}` 분포를 그대로 프론트에 넘긴다.

---

## 2. 파이프라인 안에서의 위치

| 구분 | 내용 |
|---|---|
| **입력** | `verifications.claim_results[*].metric` (7단계 생성 + 8단계 보정 결과) |
| **출력 1** | 각 `claim_result.verdict` / `mismatch_type` 을 **metric으로 확정** |
| **출력 2** | `verifications.summary` — `verdict_counts` · `overall_confidence` · `coverage` 확정 |
| **특징** | **결정적 집계**(LLM 미사용) |
| **실패 처리** | raise → runner / 7단계 미실행 등 예외 경로는 최소 골격 생성(레거시 폴백) |

---

## 3. 두 가지 일 — ① claim별 확정 ② 기사별 집계

### ① claim별 verdict 확정
- 8단계까지 보정된 `metric.verdict`를 `claim_result.verdict`(표시 필드)로 확정.
- `mismatch_type`도 metric 값으로 미러링.
- N의 세부 사유(데이터 모호/시스템 장애)는 **상류가 찍은 `needs_hitl`·`hitl_category`를 그대로 보존** — 9단계는 가공하지 않음.

### ② 기사 단위 집계 (`VerificationSummary`)

| 항목 | 산식 | 의미 |
|---|---|---|
| `verdict_counts` | `{T, F, M, N}` 카운트 | claim별 판정 분포 (원본 데이터) |
| `overall_confidence` | **T / (T+F+M)** | **검증된 것 중 사실 비율** (N 제외) |
| `coverage` | **(T+F+M) / total** | **실제 검증해낸 비율** (N=미검증) |

- `resolved = T + F + M` (판정이 선 건, N 제외).
- 비율은 카운트에서 파생 — 카운트가 원본, 프론트가 `total_claims`로 나눠 표시.
- T/F/M/N 외 값(`UNVERIFIED` 등)은 **N(검증 불가)**으로 집계.

> **왜 두 지표를 나누나?**
> - `coverage` = "우리가 **얼마나** 검증했나" (N이 많으면 낮음 — 검색·매칭 실패).
> - `overall_confidence` = "검증한 것 중 **얼마나** 사실인가" (N을 빼고 본 순수 사실성).
> 두 개를 분리해야 "검증을 못 한 것"과 "검증했더니 거짓인 것"을 혼동하지 않는다.

---

## 4. 단일 종합 라벨을 안 내는 이유

> **`verdict_counts` 분포를 그대로 프론트에 넘긴다. 옛 `overall_verdict`(단일 라벨)는 폐기.**

- 한 기사에 여러 claim이 있고 각각 T/F/M/N이 섞인다. 이걸 하나의 라벨로 뭉개면 정보 손실.
- 예) "10개 중 8개 사실, 1개 거짓, 1개 왜곡"을 "거짓 기사"로 단정하면 과도하다.
- → 분포를 보여주고 해석은 프론트(사용자)에게 맡긴다.

---

## 5. 레거시 폴백 (`_build_skeleton`)

7단계가 미실행된 예외 경로에서는 `claims`로 빈 `claim_results` 골격을 만든다.
- 각 claim에 `evidences[0]`(또는 빈 Evidence)을 붙여 최소 구조 유지.
- summary 분포·지표는 본 산출이 덮어쓰므로 기본값만.

## 7. 한 줄 정리

> 9단계는 **"claim별 판정 → 기사 단위 종합"** 집계기다.
> 핵심은 ① **metric.verdict 최종 확정**, ② **분포(verdict_counts) + 두 지표 분리**(`coverage`=검증률, `overall_confidence`=검증된 것 중 사실성),
> ③ **단일 라벨을 강요하지 않고 분포를 그대로 전달**이다. 결정적 집계라 산식 정확도 100%.
