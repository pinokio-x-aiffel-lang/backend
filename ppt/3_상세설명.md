# 3단계 — 클레임 정규화 (Normalize Claim)

> 코드: `src/modules/normalize_claim.py` · 수사 파서: `src/modules/parse_korean_number.py`
> 프롬프트: `NORMALIZE_VALUE_*` / `NORMALIZE_PERIOD_*` (`src/prompts/prompts.py`)
> 파이프라인 등록명: **"한국어 수사 산술로 변환"** (`src/pipeline/runner.py`, step 3)

---

## 1. 한 줄 정의

> **2단계가 뽑아낸 claim의 "수치 원문(raw)"과 "시점 원문(raw)"을, 기계가 비교할 수 있는 표준 산술값(`llm_value`)으로 변환하는 단계.**

기사에는 `"8만3000명 줄었다"`, `"두 배"`, `"전년 동월"`, `"작년 4분기"` 처럼 한국어 수사·상대 시점 표현이 섞여 있다.
이걸 그대로 두면 KOSIS 통계값(예: `216000`, `2024-Q4`)과 직접 비교할 수 없다.
이 단계가 끝나면 모든 claim의 수치·시점이 **숫자/표준 날짜 문자열**로 바뀌어, 이후 KOSIS 대조(4~9단계)가 가능해진다.

| 변환 예 (raw → llm_value) | |
|---|---|
| `"8만3000명 줄었다"` | → `"-83000"` |
| `"두 배"` | → `"2.0"` |
| `"3.1%"` | → `"3.1"` |
| `"삼천오백만"` | → `"35000000"` |
| `"전년 동월"` (2025-03 기사) | → `"2024-03"` |
| `"작년 4분기"` (2025 기사) | → `"2024-Q4"` |

## 2. 파이프라인 안에서의 위치

| 구분 | 내용 |
|---|---|
| **입력** | `master_schema.claims[*]`의 `value.raw`, `period_value.raw`, `compare_period_value.raw` + 기사 발행일(`article.published_at`) |
| **출력** | 같은 claim들의 `value.llm_value`, `period_value.llm_value`, `compare_period_value.llm_value` (원문 raw는 보존) |
| **처리 단위** | 모든 claim **병렬**(`asyncio.gather`) |
| **다음 단계로** | 4단계(KOSIS 통계표 검색)가 정규화된 값으로 후보 검색 |

> **`raw`는 보존하고 `llm_value`에 정규화 결과를 채운다.** (`ValueSlot` 구조: `raw` / `llm_value` / `is_inferred`)
> 즉 원문과 변환값을 둘 다 들고 가서, 하류에서 추적·디버깅이 가능하다.

---

## 3. 핵심 설계 — "룰 베이스 우선, LLM은 최후의 1회"

이 단계의 가장 중요한 아키텍처는 **2단 캐스케이드**다.

```
raw 값
  │
  ├─① 룰 베이스 (정규식·파서, 동기·결정적)  ← 대부분 여기서 해결
  │      성공 → 표준값 반환
  │      실패 → None
  │
  └─② LLM 폴백 (HCX-005)  ← 룰이 전부 실패했을 때만, 단 1회
         · 시점은 게이팅 통과해야만 호출(환각 차단)
         · 그래도 실패 시 → raw 원문 그대로 반환
```

**왜 룰을 먼저, 전부 시도하나?**
- 결정적·재현 가능·빠름·무비용. 한국어 수사/시점은 패턴이 유한해 룰로 대부분 커버된다.
- 과거엔 한국어 수사 파서의 LLM 폴백이 아라비아+`만` 수치보다 **먼저** 끼어들어, `'아라비아+만'`을 환각으로 ×10/×100/×1000 오스케일하던 버그가 있었다. → **룰을 전부 먼저 시도하고, LLM 폴백은 `_resolve_value`에서 단 한 번만** 호출하도록 고정.

## 4. 정규화하는 3개 슬롯

| 슬롯 | 의미 | 정규화 방식 |
|---|---|---|
| `value` | 주장의 수치 | 수치 정규화 (`_resolve_value`) |
| `period_value` | 주장의 주 시점 | 시점 정규화 (`_resolve_period`, base=발행일) |
| `compare_period_value` | 비교 기준 시점 (증감의 기준) | 시점 정규화하되 **base=발행일이 아니라 주 시점** |

처리 순서(`_normalize_one`):
1. `value`와 `period_value`를 **병렬**로 정규화.
2. `compare_period_value`는 **주 시점이 정해진 뒤**, 그 값을 base로 삼아 후처리.

> ⚠️ **비교 기준 시점은 발행일이 아니라 주 시점에서 빼야 한다.**
> 예) 주 시점이 `2025-03`인 claim의 `"전년 동월"`은 **2024-03**이다.
> 만약 발행일(예: 2025-05) 기준으로 풀면 발행월 기준으로 어긋나 → 증감 비교가 `NEI`(검증불가)로 빠진다.
> 그래서 `cmp_base = claim.period_value.llm_value or base`.

## 5. 수치(value) 정규화 — 처리하는 모든 유형

`_parse_value`가 아래 순서로 룰을 시도한다: **범위 → 증감 → 비율 → 한국어 수사 → 아라비아+큰수단위**.

### 5-1. 범위 표현 (`_try_range`)

| 유형 | 입력 | 출력 |
|---|---|---|
| 부터~까지 | `"50부터 100까지"` | `"50~100"` |
| 틸드(단위 접미사 허용) | `"1850~1950원"` | `"1850~1950"` |
| 틸드(만/억 풀이) | `"100만~200만"` | `"1000000~2000000"` |
| 이상 | `"100 이상"` | `">=100"` |
| 이하 | `"5% 이하"` | `"<=5"` |
| 초과 / 미만 | `"3 초과"` / `"3 미만"` | `">3"` / `"<3"` |
| 최대 / 최고 | `"최대 5"` | `"<=5"` |
| 최소 / 최저 | `"최소 3"` | `">=3"` |

(종결어미 `이다/이라/입니다/였다` 등이 붙어도 포착)

### 5-2. 증감 표현 (`_try_change`) — 부호로 방향 표현

| 유형 | 입력 | 출력 |
|---|---|---|
| 배수(아라비아) | `"2배"` | `"2.0"` |
| 배수(고유어) | `"두 배"` | `"2.0"` |
| 갑절 | `"갑절"` | `"2.0"` |
| % 증가/감소 | `"3% 증가"` / `"5% 감소"` | `"+3.0"` / `"-5.0"` |
| 단위 동반 증감 | `"21만6000명 증가"` | `"+216000"` |
| 단위 동반 증감 | `"2290억원 줄었다"` | `"-229000000000"` |
| 방향어만 | `"증가"` / `"감소"` | `"+"` / `"-"` |

- 증가 방향어: `증가·급증·상승·늘어·올라·올랐·오를·증대·늘었`
- 감소 방향어: `감소·급감·하락·줄어·내려·하강·감축·내렸·줄었·낮췄·낮아졌`

### 5-3. 비율 표현 (`_try_ratio`)

| 유형 | 입력 | 출력 |
|---|---|---|
| A대B | `"3대 5"` | `"3:5"` |
| 할·푼·리·모 | `"3할5푼"` | `"0.35"` |
| N분의 M | `"3분의 1"` | `"0.3333"` |
| A/B 분수 | `"1/3"` | `"0.3333"` |
| 절반·반·과반 | `"절반"` | `"0.5"` |
| 퍼센트 | `"3.1%"` | `"3.1"` |

> ⚠️ **% 값은 ÷100 하지 않는다.** KOSIS가 % 지표를 `3.1` 스케일로 주므로, 맞춰서 `"3.1%"→"3.1"`로만 변환.
> 단위 `%`는 `claim.unit`에 따로 보존된다.
> `A/B` 분수는 날짜(`2025/03`, `2024/12/31`)와 충돌하지 않도록 4자리 연도 패턴은 제외.

### 5-4. 한국어 수사 (`parse_korean_number.py`)

| 유형 | 입력 | 출력 |
|---|---|---|
| 한자어 수사 | `"삼십이"` | `"32"` |
| 한자어 + 큰수단위 | `"오천억"` | `"500000000000"` |
| 한자어 + 큰수단위 | `"삼천오백만"` | `"35000000"` |
| 고유어 수사 | `"스물셋"` | `"23"` |
| 서수 | `"제3"` | `"3"` |

- 큰 수 단위: `경(10¹⁶)`, `조(10¹²)`, `억(10⁸)`, `만(10⁴)` + 소단위 `천/백/십`.
- 아라비아+큰수단위 폴백(`_parse_number_rule`): `"5,231억"` 같은 혼합 표기를 숫자로.

## 6. 시점(period) 정규화 — 처리하는 모든 유형

`_normalize_period(raw, base)` — base는 기사 발행일. 출력 형식은 아래 4종.

### 출력 표준 형식

| 형식 | 의미 | 예 |
|---|---|---|
| `YYYY` | 연 | `2024` |
| `YYYY-MM` | 월 | `2024-03` |
| `YYYY-Qn` | 분기 (n=1~4) | `2024-Q4` |
| `YYYY-H1` / `YYYY-H2` | 상/하반기 | `2024-H1` |

### 6-1. 절대 표기 (base 불필요)

| 입력 | 출력 |
|---|---|
| `"2024년 3월"` | `"2024-03"` |
| `"2024/03"`, `"2024.03"` | `"2024-03"` |
| `"2024년 4분기"` | `"2024-Q4"` |
| `"2024년 상반기"` / `"하반기"` | `"2024-H1"` / `"2024-H2"` |
| `"2024회계연도"` | `"2024"` |
| `"2024년 이후/이전/부터/까지"` | `"2024"` |
| `"2024년"`, `"2024"` | `"2024"` |

### 6-2. base 의존 상대 표기 (발행일 기준 계산)

발행일을 `(by=연, bm=월)`로 파싱한 뒤 상대 표현을 절대값으로 환산.

| 입력 | 출력 (by=발행연, bm=발행월 기준) |
|---|---|
| `"전년"`, `"작년"`, `"지난 해"` | `by-1` |
| `"재작년"`, `"지지난 해"` | `by-2` |
| `"전년 동월"` | `(by-1)-bm` |
| `"전년 동기"` | `(by-1)-Q(해당분기)` |
| `"작년 4분기"` | `(by-1)-Q4` |
| `"작년 상/하반기"` | `(by-1)-H1` / `H2` |
| `"작년 말"` / `"작년 초"` | `(by-1)-12` / `(by-1)-01` |
| `"전월"`, `"전달"`, `"지난 달"` | `bm-1` 개월 (연도 넘김 처리) |
| `"전분기"`, `"지난 분기"` | 직전 분기 (연도 넘김 처리) |
| `"올해 N월"`, `"금년 N월"` | `by-NN` |
| `"올해"`, `"금년"`, `"이번 해"` | `by` |
| `"이번 달"`, `"당월"`, `"이달"` | `by-bm` |
| `"이번 분기"`, `"당기"` | `by-Q(해당분기)` |
| `"N분기"` (연도 없음) | `by-Qn` |
| `"전반기"` / `"이번 반기"` | 발행월로 H1/H2 판정 |
| `"N년 전"` / `"N년 후"` | `by∓N` |
| `"N개월 전"` | 월 오프셋 계산 |
| `"연말"` / `"연초"` | `by-12` / `by-01` |

> 세부 패턴(동월·동기·분기·반기·말·초)을 **포괄 연도 패턴보다 먼저** 매칭하도록 순서를 잡아, `"작년 4분기"`가 단순 `by-1`로 뭉개지지 않게 한다.

## 7. LLM 폴백 — 언제 호출하고, 언제 막나

룰이 `None`을 반환하면 LLM(HCX-005)으로 폴백한다. 단, **시점**은 환각 방지를 위해 게이팅을 통과해야만 호출한다.

### 수치 LLM 폴백 (`_llm_normalize_value`)
- 룰이 전부 실패할 때만 1회 호출. 실패 시 raw 원문 반환.
- 프롬프트 규칙: 큰 수 단위 풀이(`'오천억'→'500000000000'`), 증감은 부호(`'3% 증가'→'+3.0'`), 범위는 `'50~100'`, 숫자 문자열 하나만 출력.

### 시점 LLM 폴백 게이팅 (`_llm_fallback_allowed`) — 그럴듯한 환각 차단

| 조건 | 처리 |
|---|---|
| raw에 절대 연도(4자리) 포함 | ✅ 허용 (base 불필요) |
| 상대 표현인데 기준 연도(base) 없음 | ❌ 차단 |
| 월 단위 해소 필요(`달/월/분기/반기`)한데 base에 월 없음 | ❌ 차단 |
| 일 단위(`N일`)만 있고 월 표현 없음 | ❌ 차단 (표준 형식 Y/M/Q/H로 표현 불가) |

- 폴백 출력도 `YYYY(-MM|-Qn|-H1/2)` 형식에 정규식으로 맞을 때만 채택, 아니면 raw 유지.

> **게이팅의 의미:** base 정보가 부족하면 LLM이 "그럴듯하지만 틀린" 날짜를 지어낼 수 있다.
> 차라리 변환을 포기(raw 유지)하는 것이 환각 채택보다 안전하다는 설계.

| 폴백 | 모델 | max_tokens | temperature |

## 9. 성능 (벤치마크 `benchmark/3_normalize/leeaain_260619_01.md`)

260619 캐스케이드 평가 (상류=파이프라인 출력 input, 독립 gold):

| 지표 | 값 | 95% CI |
|---|---|---|
| value accuracy | **1.000** (22/22) | [0.851, 1.000] |
| period accuracy | **0.238** (5/21) | [0.106, 0.451] |

**해석**
- **수치 정규화는 채점 행 전부 정답** — 룰 베이스가 한국어 수사·증감·비율·범위를 안정적으로 커버.
- **시점 정규화 정확도가 낮은 건 캐스케이드 특성** — 상류(2단계 추출)에서 잘못 들어온 시점/발행일 누락이 그대로 전파됨. (scorable 행만 분모, 표본도 작음)
- 모듈 격리 기준 별도 평가(gold 100건)에서는 accuracy 0.559 — **만/억 100배·분기→월 오인·범위+단위·count 부호** 가 주요 오류원으로 식별됨.

## 10. 한 줄 정리

> 3단계는 **"한국어 수사·상대 시점 → 기계 비교 가능한 표준 산술값"** 변환기다.
> 핵심은 ① **룰 베이스 우선 + LLM 최후 1회**(결정성·환각 방지), ② **수치/시점/비교시점 3슬롯** 정규화,
> ③ **% 스케일 보존·비교시점은 주시점 기준**이라는 도메인 규칙이며, 이 표준값으로 비로소 KOSIS 대조가 가능해진다.
