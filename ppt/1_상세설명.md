# 1단계 — 기사 내용 확인 (Load Article)

> 코드: `src/modules/load_article.py` · 사이트 추출기: `src/article/{generic,naver,chosun,asiae,newstapa,ohmynews}`
> 파이프라인 등록명: **"기사 내용 확인"** (`src/pipeline/runner.py`, step 1)

---

## 1. 한 줄 정의

> **사용자가 넣은 입력(기사 URL 또는 본문 텍스트)을 받아, 검증 파이프라인이 쓸 수 있는 `Article` 객체(제목·본문·발행일·출처)로 변환하는 첫 단계.**

이후 모든 단계는 `master_schema.article`을 입력으로 시작한다. 그래서 이 단계의 산출물 품질(특히 **본문 정확 추출**과 **발행일**)이 전체 파이프라인의 토대가 된다. (발행일은 3단계 상대 시점 정규화의 base가 된다.)

---

## 2. 파이프라인 안에서의 위치

| 구분 | 내용 |
|---|---|
| **입력** | `master_schema.content` — 기사 **URL** 또는 **본문 텍스트** |
| **출력** | `master_schema.article` : `Article`(article_id·title·content·published_at·source·url) |
| **다음 단계로** | 2단계(claim 추출)가 `article.content`를, 3단계가 `article.published_at`를 사용 |
| **실패 처리** | `LoadArticleError` raise → runner가 `StepEvent(error)` |
| **NOTE** | 내부 처리(fetch·파싱)는 전부 **동기** — 단계 규약상 시그니처만 `async` |

---

## 3. 입력 종류 판별 — URL인가, 본문인가

`_is_url`: content가 `http://`·`https://`로 시작하면 URL, 아니면 본문 텍스트.

```
content
  ├─ URL 형태       → _load_from_url (방문·크롤링·추출)
  └─ 그 외(본문)    → _load_from_text (content만 담고 메타는 None)
```

### 본문 텍스트 입력 (`_load_from_text`)
- 메타데이터 없이 `content`만 담는다.
- `published_at`은 **DUMMY = `"2025-04"`** (상대 시점 계산 테스트용). 실데이터 연결 시 None/추출값으로 교체 예정.

---

## 4. URL 입력 처리 (`_load_from_url`)

### ① HTML fetch (`_fetch_html`)
- 브라우저류 User-Agent로 요청(일부 언론사가 기본 UA 차단), timeout 15초, redirect 허용.
- **인코딩 보정**: requests는 charset 없는 응답을 ISO-8859-1로 가정 → 한글 사이트(UTF-8·EUC-KR)를 위해 `apparent_encoding`(본문 기반 감지)으로 교정.

### ② 본문·메타 추출 — 2단 구조
**일반 경로(`generic`) + 사이트 전용 보정(`_refine_by_site`)**

| 사이트 | 추출 방식 | 이유 |
|---|---|---|
| **네이버** | 전용 추출(`naver`) + 셀렉터 자가복구 | 표준 메타에 게시일·원매체 없음 |
| 그 외 일반 | JSON-LD / OG 경로(`generic`) | 표준 마크업 |
| **조선** | `window.Fusion`에서 본문 복구 | 본문이 JS 렌더라 일반 추출 시 0자 |
| **아시아경제** | `#txt_area` 문단으로 복구 | JSON-LD articleBody가 95자 티저뿐 |
| **뉴스타파** | Editor.js 본문 + 게시일·매체명 보강 | 표준 메타 부족 |
| **오마이뉴스** | `<figure>`/`[편집자말]` 정제 + 매체명 한글화 | 본문에 노이즈 혼입 |

- `_refine_by_site`: 사이트 전용 추출값이 **있을 때만** 일반 추출값을 덮어쓴다.
- `_overlay`: 사이트 전용 메타로 덮어쓰되 None/빈 값은 무시.

---

## 5. 추출하는 `Article` 필드

| 필드 | 의미 | 본문 입력 시 |
|---|---|---|
| `article_id` | 기사 식별자 | `"art-0001"` 고정 |
| `title` | 제목 | None |
| `content` | **본문 (핵심)** | 입력 그대로 |
| `published_at` | 발행일 (3단계 상대시점 base) | DUMMY `"2025-04"` |
| `source` | 출처 매체 | None |
| `url` | 원문 URL | (없음) |

---

## 6. 설계 포인트

- **본문 정확 추출이 최우선**: favor_recall(과포함) 대신 chosun 베이스를 채택 — favor_recall=True는 본문이 아닌 boilerplate·타기사 헤드라인을 주입해서 기각(재검증 완료).
- **사이트별 비표준 마크업·JS 렌더**를 전용 추출기로 보정해, 일반 경로로는 0자가 나오는 케이스(조선·아시아경제 등)를 복구.
- **런타임 크롤링은 `requests` 동기 래퍼** — 단계 규약상 함수만 `async`로 감싼다.

---

## 7. 한 줄 정리

> 1단계는 **"URL/본문 → 정제된 Article"** 적재기다.
> 핵심은 ① **입력 종류 판별**(URL vs 본문), ② **인코딩 보정 + 일반(JSON-LD/OG) 추출 + 사이트 전용 보정** 2단 구조,
> ③ **본문 정확 추출 우선**(boilerplate 주입 기각)이다. 이 산출물(특히 본문·발행일)이 전체 파이프라인의 토대가 된다.
