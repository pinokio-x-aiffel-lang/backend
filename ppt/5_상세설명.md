# 5단계 — KOSIS 셀 값 조회 (Fetch KOSIS Data)

> 코드: `src/modules/fetch_kosis_data.py` · 좌표 매핑: `src/kosis/map_claim_to_cell.py`
> 셀 조회: `src/kosis/cell.py`(`fetch_cell_with_retry`, `statisticsParameterData.do`) · 메타: `src/kosis/metadata.py`
> 프롬프트: `RESOLVE_AXIS_MATCH_*` (`src/prompts/prompts.py`)
> 파이프라인 등록명: **"KOSIS 셀 값 조회"** (`src/pipeline/runner.py`, step 5)

---

## 1. 한 줄 정의

> **4단계가 찾아온 후보 통계표들 안에서, claim이 가리키는 정확한 "셀 한 칸(항목 × 분류축 × 시점)"을 좌표로 찍어 실제 통계값을 읽어오는 단계.**

통계표는 2차원 격자다. 같은 표 안에도 `제조업 × 남성 × 2024년 3월` 처럼 항목·분류·시점 조합마다 값이 다르다.
이 단계는 claim의 `subject·population·period`를 표의 **항목(itmId)·분류축(objL)·시점(prdDe)** 코드로 번역해서, KOSIS에서 **그 한 칸의 숫자**를 가져온다. 이게 검증의 "정답값(증거)"이 된다.

---

## 2. 파이프라인 안에서의 위치

| 구분 | 내용 |
|---|---|
| **입력** | `master_schema.analysis[*].candidates` (4단계 후보표) + 해당 `claim` |
| **출력** | `analysis[*].evidences` : 매칭된 셀들(`Evidence`, RANK 순) — **고르지 않고 매칭된 셀 전부** |
| └ | `analysis[*].kosis_query` : 조회 로그(성공/실패·파라미터) |
| └ | `analysis[*].cell_attempts` : 표별 조회 시도 기록(왜 못 찾았는지 디버깅용) |
| **처리 단위** | claim 간 **병렬**(`gather`) + 한 claim의 후보표 간 **병렬**(`to_thread`+`gather`) |
| **실패 격리** | claim 실패(`KosisError`/`ClaimMappingError`/`ValueError`)는 `success=0` 기록 후 계속 |

> 이 단계는 표를 **1개로 좁히지 않는다.** 매칭된 모든 후보 셀을 `evidences`로 내보내고, **표 선정은 6단계(rank_evidence), n:1 비교는 7단계**가 한다.

## 3. 핵심 설계 — "결정적 매칭 먼저, LLM은 미스에만 (2-pass)"

좌표 매핑(claim → 셀 코드)은 비용·환각 통제를 위해 **2단계(2-pass)**로 한다.

```
[Pass 1] 결정적 조회 (규칙 + 동의어, LLM 미사용)
   · 후보표 전체를 동시 조회 (early-stop 없이 전부 시도)
   · subject→항목(itmId), population→분류축(objL) 이름 매칭
   · 모집단 특정값을 얻은 표가 있으면 → 끝
        │
        ▼  (실패/모집단 폴백일 때만)
[Pass 2] LLM 폴백 재조회 (HCX-007)
   · 항목(itmId) 미매칭 또는 모집단 폴백/미매칭 후보를 RANK 순으로
   · 분류축 + 항목 둘 다 LLM 매칭 주입
   · claim당 최대 5개(_PASS2_LLM_CAP)까지, 첫 성공에서 중단
```

> **정책/메커니즘 분리:** 좌표 매핑 모듈(`map_claim_to_cell`) 자체는 **LLM 의존 없이 결정적**으로 유지하고, "LLM을 부를지 말지(비용)"는 후보 전체를 보는 상위 함수(`fetch_kosis_data`)가 결정한다.

## 4. 좌표 매핑 — claim을 셀 코드로 번역 (`map_claim_to_cell`)

선정 표의 메타데이터(`getMeta` ITM+PRD 병렬 → `TableMetadata`)에서 항목·분류축을 받아 매핑한다.

### 매핑 대상 3종

| claim 필드 | → KOSIS 좌표 | 매칭 방법 |
|---|---|---|
| `subject` | 항목 `itmId` | 표의 항목 목록에서 이름 매칭 (실패 시 매핑 실패) |
| `population` | 분류축 `objL1~4` | 분류축 값에서 이름 매칭, 실패 시 **합계 코드 폴백** |
| `period` | 시점 `prdDe` + `prdSe` | 주기 코드 변환 (아래 §6) |

### 이름 매칭 규칙 (`_match_code`)
- **정규화(`_norm`)**: 공백·하이픈·물결(`-‐―~`) 제거 → `"15 - 29세"`·`"15~29세"` 동일화.
- **동의어 확장(`_expand` + `synonyms.py`)**: claim `"청년"` → 축값 `"15~29세"` 갭을 메움.
- **정확 일치 우선 → 부분 일치**(부분이면 가장 짧은 이름=더 구체적 선택, substring 함정 회피).

### 모집단 합계 폴백 (`_total_code`) — 중요한 안전장치
population을 어느 분류축에도 못 박으면, 그 축은 **합계/전체 카테고리**로 대체한다.

| 단계 | 처리 |
|---|---|
| ① 정확 매칭 | `계·전체·합계·전국·소계·총계` |
| ② 접미사 매칭 | `"15세 이상 전체"`처럼 총계가 장황한 축 (끝이 `전체/합계/총계/소계/전국`) |

> ⚠️ **`population_fallback` 플래그:** 요청 집단을 못 맞춰 "전체값"으로 대체했으면 이 셀은 "요청 집단의 값"이 아니다. → `population_fallback=True`로 표시해 하류가 알 수 있게 한다. (첫 두 축은 합계도 없으면 매핑 실패, 3번째+ 축은 `""`로 두고 retry가 `ALL`로 확장)

### 미지원 케이스
- 분류축이 **4개 초과**면 미지원(`분류축 N개(>4) 미지원`).
- 항목(itmId) 매칭 0건이면 매핑 실패(`itmId 매칭 실패`).

## 5. LLM 분류축 매칭 폴백 (`_llm_axis_matcher`, Pass 2)

규칙+동의어가 실패한 **축/항목**에만 LLM(HCX-007)을 주입한다.

- **닫힌 보기 중 선택(+기권)** 방식이라 환각 위험 낮음 — 보기에 없는 코드를 지어내면 매핑 모듈이 한 번 더 대조 검증해 차단.
- 프롬프트 규칙:
  - 반드시 **보기에 존재하는 code 중 하나만** 반환(지어내기 금지).
  - 의미 일치 항목 없으면 `matched=false, obj_code=null`로 **기권**.
  - 예: 대상이 `"청년"`이고 보기에 연령대 있으면 `"15~29세"` code 선택 / 보기가 성별(남자/여자)뿐이면 **기권**.
- Structured Outputs로 `{matched, obj_code}` 강제(`obj_code`도 required — 안 그러면 코드 누락 실측).
- 토큰 폭증 방지: 보기 값은 최대 60개(`_AXIS_OPTIONS_CAP`)만 노출.

## 6. 시점 변환 — claim 시점 → KOSIS PRD_DE (`_to_kosis_period`)

| period_type | 입력 | KOSIS PRD_DE |
|:---:|---|---|
| `Y` (연) | `"2024"` | `"2024"` (4자리) |
| `M` (월) | `"2024-01"` | `"202401"` (YYYYMM) |
| `Q` (분기) | `"2024-Q1"` | `"202401"` (YYYYQQ, 01~04) |
| `S` (반기) | `"2024-H1"` | `"202401"` (YYYYHH, 01~02) |

---

## 7. 증감(change_rate)형 — 기준 시점도 같이 조회

claim_type이 `change_rate`면, **같은 셀 좌표를 비교 기준 시점(compare_period)으로 한 번 더 조회**한다.
→ `현재값 − 기준값 = 증감`을 7단계가 계산할 수 있도록 `Evidence.compare_value`/`compare_period`에 담는다.
(2단계가 `"전년 동월 대비"`를 뽑고 3단계가 정규화한 비교시점을 사용. 기준 조회 실패는 무시·`None`.)

## 8. 출력 — `Evidence` 한 건이 담는 것

매칭된 셀마다 생성. KOSIS 응답값을 그대로 싣는다.

| 필드 | 의미 |
|---|---|
| `value` / `unit` / `period` | 셀의 실제 값·단위·시점 (KOSIS 응답 그대로) |
| `compare_value` / `compare_period` | 증감형 기준 시점 셀 (있으면) |
| `subject` / `population` | claim에서 가져온 주제·대상 |
| `kosis_org_id·tbl_id·item_id` / `classification` | 출처 표·항목·분류 코드 |
| `table_name` / `last_updated` / `retrieved_at` | 표명·최종갱신일·조회시각 |
| `population_fallback` | 요청 집단 못 맞춰 전체값 대체 여부 |
| `match_source` | 모집단 매칭 출처 (`"rule"` / `"llm"`) |

선정(`_select_match`) 우선순위: **모집단을 실제로 맞춘 표(비폴백) 우선 → 없으면 합계 폴백 표**, 각 그룹 내에선 RANK(인덱스) 순.

## 10. 성능 (벤치마크 `benchmark/5_fetch/leeaain_260619_01.md`)

260619 캐스케이드 평가 (상류=파이프라인 출력 input, 독립 gold):

| 지표 | 값 | 95% CI |
|---|---|---|
| 조회 성공률(coverage) | **0.521** (112/215) | [0.454, 0.587] |
| 셀값 accuracy(조회분) | **0.375** (42/112) | [0.291, 0.467] |

**해석**
- coverage = 좌표 매핑에 성공해 셀을 읽어온 비율(절반 정도).
- accuracy = 읽어온 셀이 정답값과 일치하는 비율 — 캐스케이드라 상류(2~4단계) 오류가 그대로 전파.
- 셀 단위 recall의 핵심 병목은 **itmId 결정적 매칭**(항목명-주제 의미 갭). LLM 폴백을 Pass2로 얹었지만 여전히 개선 여지가 큼.

## 11. 한 줄 정리

> 5단계는 **"claim → 통계표 셀 좌표(항목×분류×시점) → 실제 통계값"** 조회기다.
> 핵심은 ① **결정적 이름매칭(정규화·동의어·합계 폴백) 먼저, 미스에만 LLM(닫힌 보기 선택)**,
> ② **표를 안 고르고 매칭 셀 전부를 evidences로** 내보냄(선정·비교는 6·7단계), ③ **증감형은 기준 시점도 함께 조회**.
> 여기서 비로소 "검증의 정답값"이 확보된다.
