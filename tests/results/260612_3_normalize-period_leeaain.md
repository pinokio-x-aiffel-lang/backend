## 분석 — 오답 14건의 근본 원인 4가지

| # | 원인 | 해당 케이스 | 건수 |
|---|---|---|--:|
| R1 | **포괄 `전년\|작년\|지난해` 분기가 너무 일찍 매칭** — `_normalize_period` 의 연도 포괄 분기(`return str(by-1)`)가 `전년 동월`(L205)·`전년 동기`(L208)·`작년 말`(L257)·`작년 초`(L267)보다 앞(L191)에 있어 **뒤의 세부 분기가 도달 불가(dead code)**. `작년 4분기`·`지난해 상반기`도 같은 분기에 삼켜져 분기/반기 드롭 | 전년 동월(×2), 전년 동기, 작년 4분기, 지난해 상반기, 작년 말, 작년 초 | 7 |
| R2 | **`재작년` 이 부분문자열 `작년` 으로 매칭** → by−1 (정답 by−2). R1과 같은 포괄 분기 | 재작년 | 1 |
| R3 | **`올해 N월`·`올 N분기` 세부 패턴 부재** — 포괄 `올해` 분기가 월을 드롭하거나(올해 5월→2025), 룰 미매칭→LLM 폴백이 분기를 월로 오인(`1분기`→2025-01, 어제 채점의 A4 버그 재확인) | 올해 5월, 올 1분기, 1분기, 지난 1분기 | 4 |
| R4 | **LLM 폴백이 base 불충분 시 환각** — base에 월이 없거나(`2025`) 아예 없어도(`""`) `지난달`→`2025-01`/`2023-02`를 생성, 형식 정규식을 통과해 채택됨. **해소 불가를 불가로 처리하지 못하고 그럴듯한 오답 생성** | 지난달(base=2025), 지난달(base=없음) | 2 |

수정 우선순위 제안: ① R1·R2 = 세부 패턴을 포괄 분기 앞으로 이동 + `재작년` 패턴 추가(룰 순서 변경만으로 8건 해소), ② R3 = `(올해?\s*)?([1-4])분기`·`올해 N월` 룰 추가, ③ R4 = LLM 폴백 호출 전 base 유효성 검사(월 필요 표현인데 bm 없으면 미해소 확정).

참고(R5 잠재): 절대 표기는 12/12 만점. 다만 무base `2024년 말/초` 는 **룰이 아니라 LLM 폴백으로 통과**(rule=None) — `YYYY년 말/초` 분기(L254·L262)가 base 파싱 가드(`if by is None: return None`, L179-180) 뒤에 있어 base 없으면 절대 표기인데도 룰이 포기한다. 4자리 연도 분기는 가드 앞으로 옮기는 게 맞다.
