# 2단계~10단계 모듈별 테스트 계획

본 문서는 `src/pipeline/runner.py` 의 **2~10단계 각 모듈을 독립적으로 평가**하기 위한 계획이다.
단계마다 ① 측정 지표 ② 테스트 입력 데이터 형태(JSON) ③ 최소 데이터 수 ④ gold 출처·보강을 정의한다.

> 작성: leeaain · 2026-06-14 · 대상: `src/modules/*` 10단계 중 2~10

---

### 0-1. 마스터 평가셋 (단일 진실 원천)

모든 단계 평가셋은 **하나의 마스터셋에서 파생**한다. 같은 행을 단계별 입력 스키마로 잘라내므로,
각 필드는 마스터 행 1개로 역추적(`row_id`)되고 "없는 데이터 생성"이 구조적으로 차단된다.

- 파일: `benchmark_aain/data/260605_평가셋_T_F_M_NEI_모음.xlsx` (원본 CSV에서 추출·라벨링)
- 파싱 스파인: `benchmark_aain/data/260614_master_eval_213_parsed_human_checked.jsonl` (읽기전용 파싱본)
- 규모: **213행** — `T(일치) 123 / F(불일치) 30 / M(오도) 30 / NEI(검증불가) 30`
- 컬럼: `기사 텍스트`, 라벨(T/F/M/NEI), `원래 통계표 수치`(공식값 — **True 123행만** 기재)

### 0-2. 무생성 원칙

값은 다음 세 출처에서만 온다. 그 외 어떤 값도 지어내지 않는다.

1. **마스터 xlsx** — 텍스트, verdict 라벨, True행 공식값
2. **기존 실제 gold** — `2_claim_extractor_output.jsonl`(2단계), `3_normalize_claim_100_gold.jsonl`(3단계)
3. **라이브 캡처** — 실제 파이프라인 1회 실행으로 얻은 실제 KOSIS/LLM 산출(candidates·evidences·정규화값·verdict)

기존 파일은 전부 **읽기 전용**, 출력은 `benchmark_aain/` 아래 신규 파일만.

### 0-3. 2-레이어 구조 (input ≠ gold)

각 평가셋 행 = `row_id`(마스터 역추적) + **input** + **gold** 로 분리한다.

- **input** = 그 단계가 실제로 받는 형태. candidates·evidences 등은 **라이브 캡처**로만 얻는다.
- **gold** = 마스터의 라벨/공식값/주석.

이렇게 해야 상류 버그와 무관하게 "그 모듈만의 성능"을 잰다(모듈 격리). verdict 정답은
캡처가 아니라 **사람 라벨**을 쓴다(아래 0-4).

### 0-4. F·M 공식값 처리 (옵션 ②)

F·M 행에는 공식값이 비어 있다. 처리 방식:

- 공식값(`kosis_value`)은 **라이브 KOSIS 캡처**로 채우고 `*_source: "live_capture"` 로 출처 표시 — 모듈 **입력/표시용**.
- 맞고 틀림의 **정답(gold verdict)은 사람 라벨**을 그대로 사용 — 캡처값으로 정답을 재정의하지 않는다.
- **안전장치**: 캡처값이 라벨과 정합한지 검사(`consistency_flag`). F는 `기사값 ≠ 캡처값`, M은 `기사값 ≈ 캡처값` 이어야 정합. 어긋나는 행은 자동 채점 대신 **검토 플래그**로 분리하고, 지표를 "플래그 제외/포함" 둘 다 보고한다.

### 0-5. 공통 주의 (지표 신뢰성)

- **클래스 불균형**: T 123 vs F/M/NEI 각 30. 단계별로 필요한 클래스만 뽑으면 표본이 작아진다(특히 8단계 M=30). 지표에 **신뢰구간/보수 해석**을 명시한다.
- **도메인 편향**: 전부 조선일보 통계 인용 문장 → 일반화 지표로 과신 금지.
- **NEI 활용**: 4·5·6단계에선 NEI 행을 "정답=조회 실패/해당 없음"인 음성 케이스로 재활용해 표본을 키운다.

## 2단계 · 클레임 추출 (extract_statistical_claims)

기사 본문에서 수치 기반 통계 주장을 추출하고 `claim_type` 을 분류한다. (입력: 기사 텍스트 → 출력: `sentences`, `claims`)

### 측정 지표
- **문장 단위 P/R/F1** — 통계 주장 문장을 양성으로 골라내는 정밀도/재현율 (음성=비수치 문장 포함 필수)
- **claim_type 분류 정확도** — 7유형(absolute/change_rate/ratio/distribution/comparison/metaphoric/verifiable) + none
- **슬롯 채움 정확도** — subject / value_raw / unit / period_raw / population / cited_source
- **추출률(coverage)** — 수치 보유 문장(양성)에서 claim ≥1 추출 비율

### 입력 데이터 형태 (JSON)
```json
{"provenance": "claim_extractor_100", "src_id": 1, "label": "positive",
 "claim_type_gold": "증감", "src_text": "올해 우리나라 경제성장률 전망치를 …낮췄다.",
 "gold_n_claims": 1, "gold_claims": [{"claim_id": "clm-0001", "subject": "경제성장률",
 "value": {"raw": "1.5%"}, "unit": "%", "period_value": {"raw": "올해"}, "population": "대한민국"}]}
{"provenance": "master", "row_id": 1, "verdict_label": "T", "label": "positive",
 "src_text": "9일 통계청이 발표한 …취업자 수는 2858만9000명으로…", "is_claim_bearing": true,
 "gold_claims": null, "_also_in_claim_extractor_100": true}
```
- `claim_extractor_100`: 슬롯 gold 보유(양성50+음성50) → P/R/F1·slot 채점용
- `master`: 마스터 213(전부 수치문장=양성). 슬롯 gold 미주석(null) → 추출 여부(coverage)만 검증

### 최소 데이터 수
- **필요 최소**: 양성 50 + 음성(hard-negative) 50 = **100** (슬롯 gold 포함)
- **현재 확보**: 100(gold) + 213(마스터 양성) = **313행**
- 음성(비수치 문장)은 마스터에 없어 기존 50을 반드시 합쳐 정밀도 측정

### gold 출처 / 보강
- 출처: `2_claim_extractor_output.jsonl`(기존 실제 gold), 마스터 텍스트
- 보강(gap E): 마스터 213행의 슬롯 gold는 미주석 — 슬롯 정확도까지 보려면 추가 라벨링

## 3단계 · 정규화 (normalize_claim)

claim 의 value·period·compare_period 의 raw 표현을 표준값으로 정규화한다. (룰 베이스 → LLM 폴백)

### 측정 지표
- **value 정규화 정확도** — 절대값/증감(±)/비율/범위/한국어수사 → 표준 수치
- **period 정규화 정확도** — 상대·절대 시점 → `YYYY` / `YYYY-MM` / `YYYY-Qn` / `YYYY-Hn`
- **compare_period 정확도** — 비교 시점
- **룰 vs LLM 폴백 비율** — 결정적 처리 커버리지

### 입력 데이터 형태 (JSON)
```json
{"provenance": "normalize_100", "src_id": 1, "row_id": 1, "base": "2025-04",
 "value": {"raw": "2858만9000명"}, "period_value": {"raw": "지난 3월"},
 "compare_period_value": {"raw": "전년 동월"},
 "gold": {"value": {"expected": "28589000", "match": "num", "kind": "절대값"},
          "period": {"expected": "2025-03", "match": "exact"},
          "compare": {"expected": "2024-03", "match": "exact"}},
 "src_text": "9일 통계청이 발표한 …"}
```
- `base` = 기사 발행월(상대시점 계산 기준). `match` = 채점 방식(num/exact).

### 최소 데이터 수
- **필요 최소**: ~50 (value 유형·period 유형 고르게 커버)
- **현재 확보**: **100행** (기존 hand-labeled gold 재사용)

### gold 출처 / 보강
- 출처: `3_normalize_claim_100_gold.jsonl`(기존 hand-labeled expected)
- 보강: 추가 시점/수치 변형은 마스터 True행 `gold_figures`(시점·값)로 확장 가능

## 4단계 · KOSIS 후보 통계표 검색 (retrieve_kosis_candidates)

claim.subject 로 KOSIS 통합검색을 호출해 후보 통계표 상위 N개를 수집한다. (입력: claims → 출력: `analysis[*].candidates`)

### 측정 지표
- **Recall@N / Recall@3 / Recall@1** — 정답 통계표가 상위 N 후보에 포함되는 비율
- **MRR** — 정답 표의 평균 역순위
- **검색 실패율** — `success=0`(KosisError) 비율

### 입력 데이터 형태 (JSON)
```json
{"row_id": 1, "label": "T", "subject": "취업자 수", "unit": "명",
 "period_type": "M", "population": "대한민국",
 "candidates": [{"rank": 1, "org_id": "101", "tbl_id": "DT_1DA7001S", "tbl_nm": "…", "stat_nm": "경제활동인구조사"}],
 "gold_tbl_id": null,
 "gold_item_hint": "취업자 수"}
```
- `candidates` = 라이브 캡처(실제 검색 결과 상위 N). `gold_item_hint` = True행 공식값의 항목명(검증 보조, gold 아님).

### 최소 데이터 수
- **필요 최소**: 정답 `tbl_id` 가 주석된 claim **≥50**
- **현재 확보**: 후보 캡처는 213행 전부, **`gold_tbl_id` 주석은 보강 필요**

### gold 출처 / 보강
- 출처: 라이브 캡처(candidates)
- 보강(gap C): **정답 `tbl_id`/`org_id` 주석 필요** (항목명·시점은 있으나 표 ID 없음). 주석 전까지 Recall 산출 불가 — `gold_item_hint` 로 후보 표명 매칭 보조.

## 5단계 · KOSIS 셀 값 조회 (fetch_kosis_data)

후보 표에서 claim 좌표(itm/분류축/시점)를 매핑해 한 셀 값을 조회한다. (입력: candidates+claim → 출력: `evidences`)

### 측정 지표
- **셀 값 정확도** — 조회값 == 공식 gold 값 (오차 허용 0/반올림)
- **itmId 매칭률** — subject→항목 매칭 성공 비율 (기존 병목)
- **population 매칭률 / 폴백률** — 모집단 특정 vs 전체값 대체
- **시점 매칭률** — 요청 PRD_DE 셀 존재 비율

### 입력 데이터 형태 (JSON)
```json
{"row_id": 1, "label": "T",
 "claim": {"subject": "취업자 수", "population": "대한민국", "period_type": "M",
           "period_value_llm": "2025-03", "unit": "명"},
 "candidates": [{"org_id": "101", "tbl_id": "DT_1DA7001S", "tbl_nm": "…"}],
 "captured_evidences": [{"tbl_id": "DT_1DA7001S", "value": 28589.0, "unit": "천명",
                         "period": "202503", "population_fallback": false, "kosis_item_id": "T20"}],
 "gold": {"value": 28589, "unit": "천명", "value_source": "figure", "consistency_flag": "ok"}}
```
- `captured_evidences` = 시스템 실제 출력(라이브). `gold.value` = True행은 공식값(figure), F·M은 `value_source:"live_capture"` + `consistency_flag`, NEI는 `null`(없음이 정답).

### 최소 데이터 수
- **필요 최소**: 공식값 보유 claim **≥30** (셀값 정확도)
- **현재 확보**: True 123행 공식값 有 → 충분. F·M 60행은 캡처 공식값 + 정합 플래그.

### gold 출처 / 보강
- 출처: True행 공식값(마스터), F·M 라이브 캡처값, 라이브 evidences
- 보강: 정답 `tbl_id`(4단계와 공유) — 어느 표에서 조회할지 확정 필요

## 6단계 · 증거 랭킹 (rank_evidence)

후보 표 중 주장에 '가장 적합한 표'를 LLM 으로 1위 선정(값 미사용·주제 적합도). (입력: `evidences`≥2 → 출력: 재정렬)

### 측정 지표
- **Top-1 정확도** — gold 최적 표가 `evidences[0]` 로 선정되는 비율
- **기권율** — LLM null 반환 비율
- **RANK 베이스라인 대비 개선** — 검색순위 그대로 vs LLM 재정렬

### 입력 데이터 형태 (JSON)
```json
{"row_id": 1, "label": "T",
 "claim": {"subject": "취업자 수", "population": "대한민국", "unit": "명", "period": "M:2025-03"},
 "evidences": [{"tbl_id": "DT_1DA7001S", "table_name": "…", "value": 28589.0, "axes": ["성별","연령별"]},
               {"tbl_id": "DT_1B040A3", "table_name": "…", "value": 27450.0, "axes": ["행정구역별"]}],
 "gold_best_index": 0}
```
- `evidences` = 라이브 캡처에서 **매칭 표 ≥2개**인 claim만. `gold_best_index` = True행은 공식값과 일치하는 evidence 인덱스로 도출, 그 외 보강.

### 최소 데이터 수
- **필요 최소**: 후보 표 ≥2개인 claim **≥30**
- **현재 확보**: 캡처 산출에 의존(다중후보 claim 수는 캡처 후 확정 — 부족 시 NEI/F·M 포함 확대)

### gold 출처 / 보강
- 출처: 라이브 캡처 evidences, True행 공식값(정답 표 도출)
- 보강(gap C/D): 다중후보가 적으면 정답 표 인덱스 주석 필요

## 7단계 · 통계 수치 비교 판단 (calculate_metric)

정규화된 주장 수치와 KOSIS 공식 수치를 비교해 일치(T)/불일치(F)/검증불가(N)를 판정한다. (ABSOLUTE/VERIFIABLE)

### 측정 지표
- **verdict 정확도** — 모듈 출력(T/F/N) vs gold (아래 매핑)
- **mismatch_type 정확도** — magnitude / rounding / direction
- **허용오차 경계 정확도** — within_tolerance 판정

### 입력 데이터 형태 (JSON)
```json
{"row_id": 1, "label": "T", "gold_verdict_stage7": "T",
 "claim": {"value_llm": "28589000", "claim_type": "absolute", "unit": "명"},
 "evidence": {"value": 28589.0, "unit": "천명", "population_fallback": false},
 "evidence_value_source": "figure", "consistency_flag": "ok"}
```
- **gold 매핑(7단계 기준)**: `T→T`, `M→T`(M은 값 일치 → 7단계선 T, 8단계서 M으로 강등), `F→F`, `NEI→N`.
- `evidence.value` = True행 공식값 / F·M 라이브 캡처값(+정합 플래그). 단위환산은 모듈이 수행.

### 최소 데이터 수
- **필요 최소**: T/F/N 균형 **≥50** (각 클래스 ≥15)
- **현재 확보**: T123(+M30→T) / F30 / NEI30 → 충분

### gold 출처 / 보강
- 출처: 마스터 라벨(verdict), 공식값
- 보강: F·M 공식값 정합 플래그가 'mismatch'인 행은 검토 분리

## 8단계 · 통계수치와 문장의 정합성 판단 (check_alignment)

7단계가 T(수치 일치)로 본 건의 '해석'을 재판정한다. 정합=T 유지, 오도/왜곡=M, LLM 실패=N. (T·M만 대상)

### 측정 지표
- **T vs M 분류 정확도** — 정합(aligned) vs 오도/왜곡 판정
- **mismatch 차원(dimension) 정확도** — subject/population/unit/aggregation/period
- **NEI(LLM 실패) 비율**

### 입력 데이터 형태 (JSON)
```json
{"row_id": 124, "label": "M",
 "claim": {"sentence": "2024년 합계출산율이 0.75명으로 …한 세대마다 인구가 3분의 1 토막…",
           "subject": "합계출산율", "population": "대한민국", "unit": "명",
           "aggregation": "값", "period_llm": "2024"},
 "evidence": {"table_name": "인구동향조사", "subject": "합계출산율", "population": "전국",
              "unit": "명", "period": "2024", "population_fallback": false},
 "gold": {"aligned": false, "dimension": null}}
```
- 대상 = label ∈ {T, M} (수치 일치 케이스). `gold.aligned` = `label==T`. `evidence` 메타 = 라이브 캡처.

### 최소 데이터 수
- **필요 최소**: 정합(T) ≥30 + 오도(M) ≥30 = **≥60**
- **현재 확보**: M=30(상한), T는 표본 30+ → 약 60. M이 한정 표본이라 **신뢰구간 명시**

### gold 출처 / 보강
- 출처: 마스터 라벨(T/M), 라이브 캡처 evidence 메타
- 보강(gap B): **M 30행의 오도 차원(dimension) 주석 필요** (차원별 정확도 측정 시)

## 9단계 · 종합 분석·검증 결과 생성 (decide_verdict)

claim별 metric.verdict 를 종합해 기사 단위 분포·지표를 산출한다(결정적 집계). (입력: claim_results → 출력: summary)

### 측정 지표
- **verdict_counts 정확도** — `{T,F,M,N}` 카운트
- **overall_confidence** — `T / (T+F+M)` (검증된 것 중 사실 비율, N 제외)
- **coverage** — `(T+F+M) / total` (검증해낸 비율)
- 결정적 산식 → **정확/오차 0 기대**(구현 ↔ 스펙 일치 검증)

### 입력 데이터 형태 (JSON)
```json
{"group_id": "grp-01", "scenario": "all_213",
 "note": "verdict 값은 실제 마스터 라벨; 그룹은 집계 산식 검증용 시나리오(NEI→N).",
 "claim_results": [{"row_id": 1, "verdict": "T"}, {"row_id": 184, "verdict": "F"}],
 "gold": {"verdict_counts": {"T": 123, "F": 30, "M": 30, "N": 30},
          "overall_confidence": 0.6721, "coverage": 0.8592}}
```
- verdict 값은 전부 실제 마스터 라벨(NEI→N). 그룹은 산식 검증용 시나리오(전체분포·라벨순수·혼합·경계).

### 최소 데이터 수
- **필요 최소**: 다양한 분포 **~10 그룹** (경계: 빈 그룹·단일·전부 N 포함)
- **현재 확보**: **11 시나리오** (all_213 / pure_T·F·M·N / 혼합3 / 경계3)

### gold 출처 / 보강
- 출처: 마스터 라벨 + 스펙 산식 독립 계산 → 보강 불필요(결정적)

## 10단계 · 설명 생성 (generate_explanation)

claim별 한국어 템플릿 설명(결정적) + 기사 단위 종합 의견(LLM)을 생성한다. (입력: verifications+claims → 출력: explanation·overall_opinion)

### 측정 지표
- **템플릿 설명 정확도(결정적)** — verdict별 문구 / 받침 조사(은·는) / 기간 포맷 / 출처 표기
- **종합 의견(overall_opinion) 품질** — 분포 반영·verdict와 모순 없음·환각 없음 (사람/LLM 루브릭)
- **폴백 발생률** — LLM 실패 시 결정적 템플릿 총평 사용 비율

### 입력 데이터 형태 (JSON)
```json
{"row_id": 1, "label": "T",
 "claim": {"subject": "취업자 수", "unit": "명", "period_type": "M", "period_llm": "2025-03"},
 "claim_result": {"verdict": "T", "claim_value": "28589000", "kosis_value": "28589.0",
                  "mismatch_type": null, "evidence": [{"table_name": "경제활동인구조사"}]},
 "gold_template": "기사의 2025년 3월 취업자 수 28589000명은 KOSIS 공식 수치와 일치합니다. (출처: 경제활동인구조사)",
 "opinion_rubric": ["분포 반영", "verdict와 모순 없음", "환각 없음"]}
```
- `verdict` = 마스터 라벨(T/F/M/N). 값·출처 = 라이브 캡처. `gold_template` = `_build_explanation` 스펙으로 렌더한 기대 문자열.

### 최소 데이터 수
- **필요 최소**: verdict 4종 + 받침/기간 포맷 변형 커버 **~15–20**
- **현재 확보**: 캡처 후 verdict별 표본 추출(T/F/M/N 각 ≥4)

### gold 출처 / 보강
- 출처: 마스터 라벨, 라이브 캡처 값, 결정적 템플릿
- 보강: overall_opinion 품질은 루브릭 기반 사람 평가 필요(자동화 어려움)
