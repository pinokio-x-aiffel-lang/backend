# 260617_3_nl-numeric-expr — 자연어 수치 표현 정규화 룰 점검

## 1. Overview
기사에서 포착될 자연어 수치 표현 70개를 3단계 정규화 룰(`_parse_value`, `_normalize_period`)에 그대로 통과시켜, 슬롯별(value / period_value) 현재 룰의 출력과 커버리지를 확인한다. LLM 폴백은 호출하지 않고 **룰 단독** 결과만 본다 (`None` = 룰 미스 → 런타임에선 LLM 폴백으로 넘어감).

- base(상대 시점 기준 발행일) = `2025-03-14`
- 입력: 직전 대화에서 뽑은 A(value)/B(period_value) 리스트

- period_value 22건 (기간-절대 / 기간-상대 / 기간-미커버 후보)
- 판정 3분류:

  - ⚠️ 오답/거짓정밀 — 값은 나왔지만 틀리거나 의미 왜곡(가장 위험: 조용히 통과)

### 발견된 시사점
1. **순위·"중/당/꼴" 비율은 별도 슬롯/룰 필요** — 현재는 숫자만 떼어 silent-wrong.
2. **근사 앵커형**(`약 3만`·`3만 안팎`·`3만여`·`3만 가량` → 모두 `30000`)은 점추정으로 정상 동작하나 `approx` 플래그가 없어 7·8단계 허용오차에 활용 불가.
3. **미정량 근사**(`수십만`·`수백억`·`십수`)는 거짓정밀로 잡힘 → 점추정 대신 미해소/NEI 처리 권장.
4. **슬래시·점 날짜**(`2025/03`, `2025.03`)는 `_normalize_period` 룰에 패턴 없음 → 룰 보강 시 즉시 커버 가능.
5. `지난해 말 기준`은 미커버로 분류했으나 실제 `2024-12`로 정상 커버됨.
